# 数据集固定划分版本

新的 sealed_holdout 回归建模准备会记录实际执行的一次划分。已保存到数据集库的原始数据
下面增加只读的划分版本，模型入库时关联该版本。用户可在数据概览中“查看划分”或
“复用此划分”；后者只准备新对话与固定样本文件，由用户发送新任务后开始建模。

## 数据与版本

- 复用 `nir_dataset_profiles`，使用独立的 `profile_status=split`。不新增表、不复制库内
  原始光谱文件、不修改当前 confirmed 解析版本，也不把自动记录标记成人工确认。
- 版本包含原始文件 SHA、输入文件 SHA、父解析版本、原建模会话、准确的有序样本索引、
  样本用途、所选光谱区间、划分方法和参数、完整分组数据摘要及原 CV manifest 摘要。
  完整 CV 折成员继续保留在原有私有建模会话中。
- 样本身份由原始文件及确定的解析映射绑定，不能通过文件名、样本数、比例或种子猜测。
  自动随机划分只执行一次，索引与光谱同时划分；已有固定用途保持原样。
- 挂载时按各集合原始顺序生成 CSV，保留全部所选数值与不参与样本。复用不继承旧指标、
  模型或 Test 结论，也不改变原有拟合、固定分区、封存 Test 与人工审批规则。

## 持久化与关联

`dataset_partitions.py` 读取当前所属用户和对话的私有 ingestion manifest，核对源文件、
库内不可变原件、确切挂载记录和解析版本。完整分组数组摘要必须与本次 ingestion 相同。
工作台、预览和挂载读取同样核对这个摘要；解析器变化导致结果不一致时拒绝替代读取。
库版本提交后记录私有会话的 `library_partition` 回执；两步之间中断时重试复用同一版本。
对话中的 `dataset_partition` 单独关联输出版本，原输入 Dataset/Profile/attachment 身份保持。
原件未入库、容量/规模不支持、源校验失败或存储失败均返回明确状态；私有固定划分保持。

最终模型 audit 包含这份回执。模型入库服务核对原会话、最终模型与回执、版本摘要和归属，
将该划分 Profile 保存到已有 `source_profile_id`，优先于恢复流程携带的旧输入 Profile。
新回执校验失败时拒绝以其他版本代替。报告响应中的模型来源和 dataset/Profile 一致。
读取模型报告只验证保存包与版本元数据，不打开估计器或私有 search/Test 缓存。

原始数据工作台继续读取当前 confirmed 设置。显式 `GET /workspace?profile_id=...`，
以及 `/workspace/rows`、`/workspace/spectra` 与 `/preview`，读取被指定的确切版本。
网页以 `?profile=...` 固定查看版本，禁止编辑；复用链接的 `datasetProfile` 在挂载时必须
与返回的 Profile 一致，不允许降级到最新版。

历史会话没有记录成员顺序时不补造划分版本。现有历史模型、模型包、审批、真实运行和
Docker 服务不由此代码变更自动修改。本功能覆盖当前自主单目标回归入口；既有其他训练
协议保持其原有数据与科学校验规则。工作台现有 64 MiB、5000 样本、20000 变量及
500 万矩阵元素限制继续适用。

## 回归锚点

- `backend/tests/test_nir_dataset_partitions.py`：自动保存、重试去重、精确顺序复用、父解析
  与区间保持、模型来源关联、归属校验、禁止伪造与存储失败保护。
- 既有 dataset/workspace/parsing/model/sealed-search suites：原入口兼容性。
- 前端 `dataset-partitions.test.tsx`、`api.test.ts`：版本链接、元数据与精确挂载契约。
- `frontend/tests/e2e/dataset-partitions.spec.ts`：真实浏览器渲染，后端接口拦截；覆盖固定
  版本只读查看、精确挂载和模型报告到该版本的导航，不声称生产/provider 端到端验收。
