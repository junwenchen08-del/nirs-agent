# NIR-Agent 用户使用说明

> 适用场景：使用 Docker 在本机运行 NIR-Agent，通过网页完成近红外数据检查、建模、模型保存和预测。
> 适用数据：MAT、CSV、TXT。
> 本文面向普通使用者，不要求会 Python，也不要求安装 Conda 或 `torch1` 环境。

## 1. 先了解它能做什么

NIR-Agent 可以帮助你完成下面这条流程：

```text
上传光谱文件
  → 检查数据结构
  → 确认目标变量和样本方向
  → 固定数据划分，只用校正集诊断问题并检索方法知识
  → 自动比较预处理、波长选择和建模方法
  → 查看独立留出结果
  → 人工批准模型
  → 注册并保存模型
  → 在新会话中预测新样本
  → 检查漂移并保存审计记录
```

智能体负责理解你的要求和组织步骤，实际数值计算由确定性算法工具完成。预处理和建模前，
智能体会先查询 Chemotools MCP 能力目录；Chemotools 没有合适能力或目录不可用时，才会按
项目规则使用原生补充能力。

原始单目标回归在划分后，依据校正集的噪声、基线和散射诊断，检索本地整理的
Chemotools 方法知识，优先提出有依据的预处理候选；原始光谱保留为同批对照。
交叉验证决定最终采用的方法，检索命中不表示本次数据一定受益。无匹配时明确回退到
现有规则。模型族仍沿用现有比较机制。详见 [方法知识说明](nir-method-knowledge.md)。

## 2. 第一次启动

方法知识库的日常维护入口为“设置 → 知识库 → 方法知识库”。管理员可通过表单修改方法
说明、来源、问题标签和候选参数，保存草稿或启用，测试检索并查看修改记录。
修改保存在数据目录，新的建模自动读取；无需编辑 JSON、重建镜像或启动论文 RAG。
“新增方法卡”只关联已经接入的算法；新增算法实现仍需开发与验证。
目前内置 94 张卡，覆盖官网 70 个文档条目、安装版本 MCP 的 84 项能力，保留原有
21 种预处理和 4 种回归参考。可按方法类型、算法分类、名称或用途筛选。
新增内容包含数据增强、正交投影、变量筛选、仪器迁移、异常诊断、物理转换及绘图。
MCP 参数只读显示必需输入、默认值和完整 Schema；官网参数另列，执行以当前安装
版本为准。示例数据、辅助函数及常量明确标注，不能当成建模算法。
官网的 `check_metadata_function` 尚未被当前 MCP 暴露，收录为文档参考。
展开卡片可查看适用条件、局限和参数说明，这些内容也可以在编辑表单中维护。
模型卡片用于智能体规划检索；其参数组合是参考，修改不会调整当前自动模型搜索网格。
已保存的编辑和停用状态在内置知识库升级时保留，新方法与缺失说明自动补入。

### 2.1 准备环境

需要提前安装：

- Docker Desktop；
- Git；
- `make`。Windows 建议使用 Git Bash。

项目所需的 Python、PyTorch 和 Chemotools 都在 Docker 环境中，不需要在电脑上另外创建
Python 或 Conda 环境。

### 2.2 下载项目

```bash
git clone https://github.com/junwenchen08-del/nirs-agent.git
cd nirs-agent
```

### 2.3 创建本地配置

```bash
cp config.example.yaml config.yaml
cp .env.example .env
cp extensions_config.example.json extensions_config.json
cp frontend/.env.example frontend/.env
```

然后完成两项配置：

1. 在 `config.yaml` 的 `models` 中启用一个可以调用的大语言模型；
2. 在 `.env` 中填写对应供应商的 API Key。

不要把 API Key 写进 README、截图或提交到 Git。

如果希望使用“数据集库”和“模型库”，把 `config.yaml` 中下面的开关改为：

```yaml
nir_library:
  enabled: true
```

不开启这个选项也可以上传、建模和预测，只是不能把数据集和模型保存下来供其他会话复用。

### 2.4 启动

在项目根目录运行：

```bash
make docker-start
```

第一次启动需要下载和构建镜像，时间会比以后启动长。启动完成后打开：

[http://localhost:2026](http://localhost:2026)

第一次进入页面时，按提示创建管理员账号并登录。

常用维护命令：

```bash
# 查看运行日志
make docker-logs

# 停止项目
make docker-stop
```

## 3. 第一次建模：推荐操作流程

下面以“根据近红外光谱预测药片有效成分含量”为例。其他定量任务的操作方式相同。

### 第一步：新建对话并上传文件

进入聊天页面，点击输入框旁边的附件按钮，上传 MAT、CSV 或 TXT 文件。

建议：

- 一个文件不要同时混放互不相关的多个实验；
- 光谱矩阵、波长轴和目标值的样本顺序必须对应；
- 目标值要有明确含义和单位；
- 不要上传没有合法使用权限的数据。

### 第二步：只检查数据，先不要建模

发送下面这句话：

```text
先检查我刚上传的近红外文件，只告诉我样本数、波长数、样本方向、波长轴、目标变量候选和需要我确认的映射，暂时不要建模。
```

智能体会检查：

- 哪个矩阵像光谱矩阵；
- 样本在行还是在列；
- 哪个数组是波长轴；
- 哪个字段适合作为回归目标或分类标签；
- 是否有缺失值、重复光谱或明显的数据冲突。

如果页面显示 `needs_user_mapping`，不是系统坏了，而是存在多个合理解释，系统不愿意静默
猜测。按照页面给出的候选名称回答即可，例如：

```text
确认：样本在行，NIRabs 是光谱矩阵，wv 是波长轴，active (%w/w) 是目标变量。
```

### 第三步：确认自动保存的数据集

启用数据集库后，网页成功上传的 CSV、TXT、MAT 默认自动保存，以文件名命名；
不用再向智能体发送保存指令。上传后会提示保存成功或复用已有记录，相同内容不会重复入库。
可以在左侧“光谱数据集库”中重命名。下次打开新对话，输入 `/datasets`、选择数据集、
点击“挂载到会话”，再提出建模目标。智能体仍会重新审查数据。

如果入库失败，页面会说明原因；文件仍可用于当前对话。关闭自动入库时可手动补存：

```text
确认把当前上传文件保存到数据集库，名称为 tablets-active-nir，供以后跨会话使用。
```

`nir_library.auto_save_uploads=false` 可关闭上传自动入库；模型长期保存仍遵循审批与显式保存流程。

### 第四步：提出清楚的建模目标

定量回归示例：

```text
请用 active (%w/w) 作为目标变量建立定量模型。先查询 Chemotools MCP，再自动比较合理的预处理、是否需要 CARS 波长选择以及合适的回归模型。使用独立留出集评估，不要把内部留出说成外部验证。
```

分类示例：

```text
请根据 Type 标签建立定性分类模型，使用分层独立留出，并报告 balanced accuracy、macro-F1、MCC、混淆矩阵和低置信度样本策略。
```

如果数据中有批次、仪器、产地、年份等分组字段，建议明确告诉智能体：

```text
Batch 是批次字段，划分数据时同一批次不能同时进入训练集和测试集。
```

### 第五步：等待智能体完成选择和评估

正常情况下，智能体会完成：

1. 科学有效性和数据泄漏检查；
2. 校准集、调优集和独立留出集划分；
3. 查询 Chemotools MCP 能力目录；
4. 仅用校正集诊断并检索方法知识，在校正集内交叉验证比较有依据的预处理候选与原始谱对照；
5. 判断是否值得使用 CARS 等波长选择；
6. 比较允许的模型家族；
7. 在独立留出集上给出最终指标；
8. 给出质量门禁结果和验证范围。

聊天页右上角会出现“近红外建模过程”入口。打开后可以查看阶段轨迹、当前阶段、使用的
预处理、模型、指标卡片、验证范围和下一步动作。建模产生会话文件后，面板底部可直接打开
图表与报告列表。阶段轨迹表示当前所处的步骤，不是按时间计算的完成百分比。

新建模默认交付完整 HTML 图文报告和一个统一下载包，模型、指标和图表在包内。
预处理步骤与报告会显示诊断问题、方法来源及实际采用结果，避免把检索建议当作执行结果。

如果面板显示“已阻断”或 `await_user_direction`，通常表示系统在等待你确认数据解释、模型
替换或注册操作。阅读智能体最后提出的问题并明确回答即可。

### 第六步：看懂模型结果

定量模型常见指标：

| 指标 | 大白话解释 |
|---|---|
| R² | 模型对目标值变化的解释程度，越接近 1 越好 |
| RMSEC | 模型对校准集的误差 |
| RMSECV | 交叉验证误差，用于调参和比较候选 |
| RMSEP | 独立留出集或外部测试集上的预测误差 |
| RPD | 数据标准差与预测误差的比值，通常越大越好 |
| Bias | 预测是否整体偏高或偏低，显著偏差会阻止通过 |

分类模型常见指标：

| 指标 | 大白话解释 |
|---|---|
| balanced accuracy | 各类别准确率的平均值，类别不均衡时比普通准确率更可靠 |
| macro-F1 | 每个类别 F1 的平均值，不让大类别掩盖小类别 |
| MCC | 综合评价分类结果，越接近 1 越好 |
| confusion matrix | 展示每一类被正确或错误分到哪里 |

注意：

- “通过质量门禁”不等于“已经批准上线”；
- “内部独立留出”不等于“外部验证”；
- 只有来自独立来源、未参与训练和调参的数据，才能在满足协议后称为外部验证。

如果只是使用训练数据或同源数据检查模型加载和预测流程，最终结论应明确写明：

```text
本次不得视为外部验证，也不构成新的泛化证明。
```

### 第七步：批准并注册模型

模型通过质量门禁后，系统仍会等待人工批准。可以发送：

```text
我批准当前模型进入注册阶段，请注册为 tablets-active-pls。
```

如果不认可结果，可以发送：

```text
我不批准注册。请说明当前模型的主要问题，但不要擅自换成其他模型家族。
```

“批准”表示你允许把本次通过检查的模型登记为可追溯模型，不表示它自动成为生产模型。

### 第八步：查看持久模型库的保存结果

开启模型库后，用户审批并注册成功的模型会自动保存至模型库，无需再次发出保存指令。
注册结果中会明确记录“已保存”“复用已有版本”“未启用”“按要求跳过”或“保存失败”。
模型库容量不足、文件校验失败等情况不会把“注册成功”误报为“入库成功”。
`nir_library.auto_save_registered_models=false` 可关闭自动保存；你也可以明确要求只注册、不入库。
关闭自动保存、保存失败后重试或补保存旧模型时，可以发送：

```text
确认把已注册模型 tablets-active-pls 的当前版本保存到模型库，供以后跨会话使用。
```

保存完成后，在左侧“模型库”中可以看到模型名称、版本、方法、哈希、验证范围和来源血缘。

## 4. 在新会话中使用已有模型预测

### 4.1 准备新样本

新样本必须与训练数据兼容，至少应确认：

- 同一种光谱模态；
- 波长单位和方向一致；
- 波长范围覆盖模型需要的范围；
- 每一行仍代表一个样本；
- 没有把目标答案列误当成输入光谱。

新样本可以直接上传，也可以从“数据集库”点击“挂载到会话”。

### 4.2 挂载模型

在普通网页对话输入 `/models` 并按回车，搜索模型名称、版本或算法，选择要复用的可用版本并点击“挂载到会话”。窗口会显示验证范围；已归档版本不可挂载。输入框显示模型名称与精确版本，不会自动发送消息。随后上传新数据或用 `/datasets` 选择数据，输入预测要求并手动发送。取消模型标签只取消下一条消息的选择，已挂载的会话副本仍保留。

可以在“模型库”中点击“挂载到会话”，也可以在聊天中发送：

```text
请从持久模型库挂载 tablets-active-pls 的可用版本，并用它预测当前数据。重新检查当前数据，不要继承旧会话的检查结论。
```

### 4.3 执行预测、漂移和审计

推荐发送：

```text
使用已经挂载并验证的模型预测当前样本，严格回放模型保存的预处理和波长选择，同时执行适用域漂移检查并写入预测审计。
```

预测完成后，重点查看：

- 成功预测了多少个样本；
- 预处理和波长选择是否显示为已回放；
- 是否存在漂移标记样本；
- 漂移监控状态是否为正常或告警；
- 是否生成预测 CSV、漂移状态 JSON 和审计 JSONL。

漂移标记不是说样本一定错误，而是提示这些样本与训练域差异较大，应优先复核。

## 5. 数据集库和模型库怎么用

启用 `nir_library.enabled: true` 后，左侧菜单会显示：

- “数据集库”：`/workspace/nir/datasets`；
- “模型库”：`/workspace/nir/models`。

### 数据集库

在新对话输入 `/datasets` 并按回车，可直接搜索已保存的数据集。点击“挂载到会话”只准备数据文件，输入框旁会显示已选数据集，不会自动发送消息或启动智能体。随后输入分析或建模要求并点击发送，智能体才会重新审查当前数据并执行任务。可点击数据集标签上的取消按钮，取消下一条消息的数据集选择；已挂载的会话副本仍保留。未保存的上传文件不会出现在列表中。

可以执行：

- 查看数据集名称、编号、原始文件名、大小和哈希；
- 查看或确认解析 Profile；
- 查看使用历史；
- 挂载到新会话；
- 重命名；
- 归档；
- 在满足条件时永久删除。

### 模型库

可以执行：

- 查看模型名称、版本、方法、大小和哈希；
- 查看指标、验证范围和来源血缘；
- 挂载到新会话；
- 归档；
- 在满足条件时永久删除。

归档只是隐藏资产，不会释放磁盘空间。永久删除前必须先归档，并输入页面要求的精确编号。
被活动模型引用的数据集不能删除。已经挂载到旧会话的副本不会因为删除库中版本而自动消失。

## 6. 可以直接复制的常用对话

### 只检查文件

```text
检查当前上传的近红外文件，只报告结构、样本方向、波长轴、目标变量候选和风险，先不要建模。
```

### 保存数据集

```text
确认把当前上传文件保存到数据集库，名称为 <数据集名称>，供以后跨会话使用。
```

### 自动定量建模

```text
以 <目标列> 为目标建立定量模型。先查询 Chemotools MCP，再比较合理的预处理、波长选择和回归模型；使用独立留出评估，并明确验证范围。
```

### 自动分类建模

```text
以 <标签列> 为类别建立分类模型。使用分层或分组隔离划分，报告 balanced accuracy、macro-F1、MCC、混淆矩阵和低置信度策略。
```

### 批准注册

```text
我批准当前通过质量门禁的模型，请注册为 <模型名称>。
```

### 保存模型供以后使用

```text
确认把已注册模型 <模型名称> 的当前版本保存到模型库，供以后跨会话使用。
```

### 跨会话预测

```text
从数据集库挂载 <数据集名称>，从模型库挂载 <模型名称> 的可用版本。重新检查数据后执行预测，严格回放预处理和波长选择，并启用漂移检查与预测审计。
```

## 7. 常见问题

### 页面中没有“数据集库”和“模型库”

检查 `config.yaml`：

```yaml
nir_library:
  enabled: true
```

修改后重新启动 Docker 服务。

### 系统一直要求我确认字段

说明文件中存在多个可能的光谱矩阵、波长轴或目标字段。明确告诉它变量名称和样本方向，不要
让系统猜。例如：

```text
确认 Xcal 是光谱矩阵，ycal 是目标值，wavelength 是波长轴，样本在行。
```

### 为什么模型通过了却没有注册

质量门禁通过后仍需要人工批准。明确发送“我批准当前模型进入注册阶段”。

### 为什么注册后模型库里还是没有

开启模型库后，审批并注册成功的模型默认自动保存。先查看注册返回的入库结果；如果自动保存关闭、用户明确拒绝保存，或保存因容量/校验问题失败，模型不会出现在可用列表。解决原因后，可以明确发送“把当前已注册模型保存到模型库，供以后跨会话使用”补保存。刷新模型库或 `/models` 窗口查看结果。

### 为什么不能叫外部验证

普通自动划分得到的是内部独立留出集。只有来源独立、没有参与任何训练和调参、并满足数据
来源协议的测试集，才可以称为外部验证。

### 为什么预测出现漂移样本

这些样本在训练域的 PCA T² 或 Q 残差空间中较异常。建议检查样品类型、仪器状态、波长轴、
测量条件和是否超出标定范围，不要直接删除样本。

### Chemotools MCP 不可用还能运行吗

系统会记录 MCP 查询失败，并在允许的情况下使用受治理的原生能力回退。最终结果中应能看到
提供方或回退证据。没有记录失败时，不能静默跳过 MCP-first 规则。

### Docker 启动失败怎么排查

先确认 Docker Desktop 正在运行，然后执行：

```bash
make docker-logs
```

重点查看 Gateway、Frontend 和 Nginx 是否启动。不要为了修复启动问题而删除数据库卷或
`backend/.deer-flow`，除非已经确认其中没有需要保留的数据并完成备份。

## 8. 使用边界和安全提示

- 当前推荐在可信用户的本机或单机 Docker 环境使用；不要直接把默认 `2026` 端口暴露到公网。
- 真实业务数据、数据库、模型产物、日志、API Key 和知识库索引不要提交到公开 Git 仓库。
- NIR 与 Raman 是不同光谱模态，不能作为普通的两台近红外仪器做校准迁移。
- 没有成对仪器样本时，不要使用 DS、PDS 或 SST 校准迁移。
- 模型指标好不代表可以直接用于药品放行或其他高风险生产决策；上线前仍需独立验证、审批、备份和恢复演练。
- 删除长期资产前先确认引用关系并做好备份；归档不等于备份。

## 9. 最短使用清单

如果只记住一套操作，请按下面执行：

1. `make docker-start`；
2. 打开 `http://localhost:2026`；
3. 新建对话并上传文件；
4. 先要求“只检查，不建模”；
5. 明确确认光谱矩阵、波长轴、目标列和样本方向；
6. 检查上传自动入库的提示，下次通过 `/datasets` 选择复用；
7. 要求自动建模，并说明内部留出或外部验证目标；
8. 查看近红外建模过程面板和最终指标；
9. 满意后明确批准并注册；
10. 查看注册后的自动入库结果；复用时用 `/models` 选择模型版本；
11. 新会话挂载新数据和模型，重新检查后预测；
12. 查看漂移、预测文件和审计记录。
