# ChemAgent 数据集建模过程可视化优化方案

## 1. 目标与现状

目标：让用户沿着一次数据集建模的真实执行轨迹，逐步看懂“输入是什么、做了什么、产生什么、为什么这样决定”，并在图表中探索具体证据。页面呈现已发生的事实；未执行、未记录或不可比较的内容必须明确标出。

当前聊天页的 NIR Sheet 已有“建模过程 / 选择依据 / 最终结果”页签、四阶段进度、尝试指标趋势、候选误差条形图和产物入口。它适合速览，但阶段不可点选，图表缺少悬停、筛选和联动；数据审查、拆分、预处理、特征选择、建模、验证与迭代之间也缺少连续叙事。现有工作流状态主要记录审计摘要、每轮选择事实、指标、反思和重试计划，不包含供交互图表使用的完整曲线或样本级诊断数据。因此需要同时改前端信息架构和后端图表证据契约。

## 2. 用户体验

保留现有 Sheet 作为入口和速览，增加“查看完整建模过程”，打开独立的宽屏过程探索页。桌面布局为“左侧可点的过程轨迹 / 中间主要图表 / 右侧步骤解释与证据”；窄屏改为轨迹横向滚动，图表和解释上下排列。页面顶部固定数据集、任务类型、当前状态、尝试编号、验证范围及证据更新时间。

过程轨迹由实际事件生成，不按固定比例伪造进度。推荐节点为：数据导入与解释 → 数据审查 → 数据划分 → 预处理比较 → 波长选择（适用时）→ 模型与调参比较 → 最终验证与诊断 → 反思/重试（发生时）→ 审批与注册（适用时）。每个节点有“完成 / 进行中 / 待执行 / 未记录 / 跳过 / 失败”状态。跳过节点要显示原因，例如任务不适用、用户明确指定方案或条件不满足。

点击节点后，统一展示五块内容：①本步目标；②输入和适用样本范围；③实际执行的方法、参数和操作顺序；④结果及交互图表；⑤决策依据、比较对象、阈值、证据来源和下一步。默认先显示通俗解释，再展开技术细节。节点和尝试有稳定 URL 参数，刷新后仍能回到同一位置；实时新状态到来时保留用户正在查看的节点，提示“有新进展”而不强制跳走。

尝试切换器与过程轨迹联动。选中第 2 次尝试时，预处理、波长、模型、验证及反思均展示第 2 次的事实；可选“与上次对比”，并突出改变了什么、依据是什么、指标是否改善。指标不处于相同任务、协议、验证范围、目标或单位时，不连成一条趋势线，也不标“更优”。

## 3. 各步骤的图表和交互

| 步骤 | 必须回答的问题 | 图表与交互 | 依据与边界 |
|---|---|---|---|
| 数据导入与审查 | 读入了什么，字段/方向/波长轴如何确认，有哪些质量问题？ | 数据结构卡片、波长覆盖、目标值或类别分布、缺失/异常汇总；悬停显示数量和比例，按字段切换；可放大波长区间 | 标注数据映射来源与确认状态；有歧义时显示“等待映射确认” |
| 数据划分 | 哪些样本用于校准、调参和最终验证，如何防止泄漏？ | Cal/Tuning/Test 或交叉验证分组数量图、目标/类别分布对照；点击分组看汇总 | 显示划分方法、种子或固定分组、分组隔离规则、内留出/外部来源；不展示敏感样本标识 |
| 预处理 | 原始光谱变成什么样，为什么选择这一串操作？ | 原始与处理后代表性光谱叠加、均值/分位带、候选交叉验证误差；图例开关、悬停波长、缩放、前后切换 | 标注操作顺序、参数、候选数、训练内评分及选择规则；变换仅在校准边界拟合后应用到其他分组 |
| 波长选择 | 保留了哪些区域，减少变量是否值得？ | 光谱上高亮保留波长/区间、变量数量对比、全谱与候选的调参误差；刷选区间看数量与摘要 | 显示触发条件、候选方法、最低改善要求、实际改善；不以最终测试成绩作选择依据 |
| 模型与调参 | 比过哪些模型/参数，选定方案的理由是什么？ | 同口径候选指标图、可用时的参数或潜变量数与 CV 误差曲线；悬停看参数和误差，点击候选看详情 | 清楚标出基线、选中项、训练内指标及“不适用/未运行”的候选；禁止把不同评分口径排在同一榜单 |
| 验证与诊断 | 最终预测表现如何，误差集中在哪里？ | 定量：真实值-预测值散点、残差图、指标卡；定性：混淆矩阵、各类指标与置信度分布。点选/框选后显示所选集合的汇总 | 每张图标出 Cal/CV/Tuning/Holdout/External、样本数、单位和协议；质量门禁阈值与实际值并列 |
| 反思与重试 | 为什么继续或停止，下一轮改了什么？ | 尝试时间轴、同口径指标趋势、前后方案差异；点击趋势点跳到对应尝试 | 区分“计划”“执行成功”“执行失败”；失败原因和缺失证据不包装成结果 |
| 审批与注册 | 模型是否可交付、已获谁批准、是否入库？ | 状态和证据清单、模型版本/产物链接 | 工作流注册、审批与 Model Library 入库分别标示，不能互相推断 |

交互至少覆盖：悬停显示数值、单位和数据分组；图例显隐；缩放及重置；点击候选或尝试联动详情；图表旁始终有表格或文本摘要。样本级点位如获授权，仅用本线程内的不透明 ID 做联动，默认不泄露原始光谱、参考值、路径或可跨线程关联的样本 ID。优先把聚合图做完整，再开放经授权的样本级诊断。

## 4. 数据与接口设计

工作流状态继续承载小而稳定的摘要，不把光谱矩阵、散点全集或图片 base64 塞进 `nir_workflow`。新增版本化的 `process_evidence` 索引，按 `project_id + attempt_id + step_id` 关联执行事件、方法/参数摘要、输入分组、输出指标、决策规则、证据状态和图表引用。每条事实要有 `source_tool`、执行时间、数据集哈希、协议/验证范围、目标及单位；图表须有 `chart_schema_version`、轴定义、分组与样本量。禁止由前端从文件名、聊天文本或隐藏推理猜测这些字段。

新增按线程所有权校验的只读接口，例如 `GET /api/threads/{thread_id}/nir-process`（步骤和尝试摘要）与 `GET /api/threads/{thread_id}/nir-process/attempts/{attempt_id}/charts/{chart_id}`（按需加载图表数据）。后端根据当前用户、线程、项目和证据引用核验权限，不能接受任意文件路径。返回有界、下采样或聚合后的曲线与点集；保留峰、极值、异常和分组比例等重要结构，并报告下采样方式及原始/返回点数。对缺失产物返回结构化的 `not_recorded`、`not_applicable`、`failed` 或 `unavailable`，前端显示真实状态。

建议优先复用现有 `audit_evidence`、`attempts[].decision_facts`、`metrics_summary`、`reflections`、`retry_plans` 和会话产物索引。现有 PNG 可作为“查看原始报告”入口，但不可代替可交互图表。新增绘图数据应由真实计算路径在步骤完成时生成、存放在线程受控产物区；不要让前端重新训练模型或从 PNG 逆向取数。旧会话仅展示已存在的节点和图表，缺证据就注明“当时未记录”，不静默重算或伪造。

## 5. 实施顺序

1. **过程骨架与证据清点**：把当前 Sheet 保留为速览，新建完整过程页、点击式节点、尝试切换、五块内容模板；用现有结构化状态先完成审查摘要、候选比较、指标、反思和审批的导航。梳理每个节点缺失的图表字段，形成契约样例。
2. **补齐真实图表数据**：在数据审查、拆分、预处理、选择和验证的计算路径中保存有界绘图证据，提供授权只读接口和前端按需加载。先支持最常见单目标定量任务，再补分类、多目标和固定外部验证；每种任务只显示适用图表。
3. **联动和比较**：实现缩放、图例、悬停、候选详情、尝试对比、图表与证据同步；完成空状态、失败状态、移动端与键盘交互。
4. **回归与文档**：更新中英文文案、用户指南、接口说明和示例。使用一条真实完整工作流及一条旧/缺证据工作流验收。

主要改动位置：`frontend/src/components/workspace/nir/` 的入口与过程页面组件、`frontend/src/core/nir/` 的类型/选择器/API；`backend/packages/harness/deerflow/community/nir/` 的证据生产和 `backend/app/gateway/routers/` 的授权读取接口。优先独立新增模块，保留当前未提交工作和现有审批、注册流程。

## 6. 验收标准

- 用户从聊天页进入后，三次点击以内能到任一步骤，并看到该步“做什么、输入、实际操作、结果、依据”；节点状态与后端事件一致。
- 真实单目标任务至少可交互查看数据分布、预处理前后、波长选择、候选模型和最终预测/残差；分类任务显示适用的类别图，不硬套回归图。
- 图表操作能更新数值提示和对应详情；切换尝试或节点不丢失上下文；所有图有标题、单位、分组、样本量、验证范围及文字摘要。
- 训练内选择指标与最终留出/外部验证指标在界面和数据契约上分离；不同口径不得绘制为可比较趋势；最终测试不参与候选选择。
- 未执行、缺失、失败、旧会话分别有明确状态；不能展示生成的占位数值，也不能把“注册”误写成“已入 Model Library”。
- 接口拒绝越权线程、伪造项目/路径和越界图表引用；工作流状态不含原始矩阵、样本级预测全集或宿主机路径；大数据集图表仍可流畅打开。
- 覆盖证据投影与权限的后端测试、节点/口径选择器单测，以及“点节点→看图→切尝试→看依据”的端到端测试。
