# 模型库

模型库围绕三个操作组织：找到模型、看懂模型、带到新对话中使用。

## 使用

1. 打开侧栏的模型库，通过模型名、数据集名或预测目标搜索。
2. 点击卡片查看预测效果、训练数据、处理顺序和实际保存的参数。
3. 点击“挂载到对话”或详情页的“挂载到新对话”，系统自动准备新对话并挂载该版本。
4. 添加需要预测的数据，用日常语言说明需求，再发送消息。

挂载本身不会执行预测，也不会开始训练。用户无需填写对话编号或重新设置模型参数。

预测完成后，回复显示本批样本数量、实际预测值摘要和 CSV 下载链接。模型内保存的
预处理会复用。没有参考值的新数据不能计算预测准确性，原模型的测试指标也不能当作
这批数据的指标。光谱分布偏移提示用于定位需要复核的样本，不代表已经测得预测误差。

运行时从实际 `nir_predict` 返回记录独立的预测凭据，绑定本次模型、输入、输出和审计
事件，并保存有限的摘要。新生成的预测 CSV 带有 SHA-256 校验信息。最终回复校验
触发时使用预测凭据展示结果，不再回退到建模结果提示。最近一次预测失败会替换旧的
成功凭据，挂载模型或手动标记任务结束均不能代替实际预测。回归见
`test_nir_prediction_outcome.py` 与 `test_nir_prediction_audit.py`。

## 未达门槛的模型

模型训练和测试完成后，即使评价指标未达到质量门槛，用户明确回复
“同意保存到模型库”仍可保存。卡片与详情显示“未达质量门槛，已由用户确认保存”，
原始指标和未通过的评价保持不变，模型仍可挂载用于预测。

此前因质量门槛未保存、已结束的已审批会话，可在原对话再次回复该保存指令，
复用同一份模型文件与最终指标重试保存。不会重新训练或再次评价测试集。
注册工具会核对这次新的明确同意并记录审批，避免因模型遗漏单独的审批工具调用而无法保存。
只有模型库实际写入成功后才显示已保存；保存步骤失败时会明确说明未保存。
数据科学校验、验证范围、文件完整性、来源归属和固定划分关联仍须满足原要求；
缺少质量评价不能当作用户接受的未达标模型。

实现与回归：`test_nir_quality_approval.py` 覆盖审批、包绑定、入库与挂载，以及同步和
异步的已结束会话重试。`model-library.spec.ts` 覆盖未达标提示与使用入口。

## 图表与指标

真实值与预测值对比图采用白底、蓝色或橙色样本点、红色对角线和中文坐标。
点越接近红线，预测越接近真实值。每张图标明数据分组、实际显示数量和相同分组的指标。
光谱图并列展示同一批训练样本在处理前后的曲线，并保留光谱轴顺序及已记录的单位。

R² 和 RMSE 分别按训练、调参、测试数据展示。R² 越接近 1，整体越贴近真实值；
RMSE 越小，误差越小。训练数据已经用于模型学习，调参数据已经用于选择方案，不能把这两者
当成新的独立验证。旧模型只保存了调参 R² 和测试 RMSEP 时，页面分别显示，缺失项显示横线。

数据概览复用数据集库的样本数量、光谱统计和目标分布组件。模型保存了训练解析版本时，
即使数据集后来使用了新版解析，也读取原版。早期模型没有解析版本时，页面说明概览使用当前版本。
完整数据集链接在有版本记录时打开对应的只读工作台；没有版本时打开当前数据工作台。
新自主回归模型会关联自动保存的固定划分版本，展示训练、验证、测试样本数量，并可查看原始样本用途与保留范围。

## 实现边界

- 报告接口为 `GET /api/nir/models/{model_id}/versions/{version}/report`，使用登录用户身份查找精确版本并验证保存包。
- 读取报告不反序列化模型、不读取训练数组、不执行拟合、预测或重新划分数据。
- 新模型保存时，将从已验证指标和精确训练调用中读取的报告放入原有 `metadata.json`。
  包验证、容量核算和挂载复制继续使用原机制。图表可独立于来源对话保存。
- 每张预测图最多 500 个点，每张光谱图最多 12 条曲线、256 个位置；采样保留原有结果。
- 旧记录如果没有逐样本结果或处理前后曲线，会明确说明未保存。不会通过重跑模型补齐。
- 浏览模型时没有个人空间、归档、删除和手填对话编号的流程；后端原有管理接口继续兼容。

主要回归：后端 `test_nir_model_report.py`、`test_nir_model_service.py`、
`test_nir_dataset_service.py`；前端 `model-report.test.ts`、`model-library.spec.ts`
和现有 `model-command.spec.ts`。
# 训练数据关联补充

详情接口以同一次核对结果返回一致的模型来源编号和数据集/解析版本编号，使前端
能够继续执行严格的一致性检查。历史数据库字段和模型包保持原样；仅检查 HTTP 200
不足以验收，需在真实页面确认详情、数据预览和图表均显示。

直接上传会保存数据集，但旧训练流程可能未携带数据集编号。新建模准备阶段会记录
原始输入文件的 SHA-256、大小和对话内路径；注册模型入库时，服务端核对同一用户
的数据集文件或确切挂载记录，自动保存关联和解析版本，不要求用户重新选择。

已保存模型的详情接口可以只读恢复缺失关联：先核对最终会话、模型和训练数据绑定；
旧记录没有文件哈希时，只读取有大小、矩阵规模限制的原始上传，核对完整划分身份。
不打开封存的测试缓存、不计算评价指标、不加载或重训模型。不按文件名猜测关联，
也不改写历史模型包、数据库记录或审批。无法核实的来源继续显示缺失说明。
派生数据使用原挂载记录和对应解析版本，临时核对文件在系统临时目录自动清理。
原始和模型变量数优先使用保存的维度和曲线元信息，历史缺失时不伪造数值。
