# ChemAgent 界面设计与开发方案

版本：v1.4 · 2026-10-17（修正左右高度失衡，采用等高工作区与节点分区）  
状态：已授权实施，本地源码已按本规格改版；验收与边界见 [实施记录](chemagent-ui-implementation.md)。尚未提交、推送或部署。  
适用范围：桌面 Web 为主，兼顾窄窗口可用性；中文优先，保留已有英文设置。

## 1. 目标与设计结论

将 ChemAgent 统一为「清晰、克制、易于阅读的近红外科研工作台」。用户进入任一页面，都应容易回答三个问题：我正在看什么、当前结果或状态是什么、下一步可以做什么。

本轮采用一套明确的方向：浅中性底色、白色内容面板、深色正文、青绿色交互强调、宽图表、紧凑资源卡片。保留深色主题，用同一套语义变量切换。首屏优先呈现任务、结果和主操作；建模节点的方法、参数、评价指标及 LLM 下一步建议完整展示，版本和追溯信息按需展开。

**优先级：先核验并补齐此前所有要求，再实施界面调整。任何美化都不能减少已有功能、信息或原有约束。建模过程以用户参考图中的纵向节点画布为基准，覆盖数据进入到模型保存的完整生命周期；点击节点查看该步骤真实发生的信息，方法、参数、结果指标和 LLM 下一步建议均为必备信息。有合法、对应的可视化数据时必须直接画图，不能用“可查看图表”的说明、图标、下载链接或指标数字替代图表。**

### 1.1 当前问题与对应措施

| 实际观察 | 设计措施 | 验收结果 |
| --- | --- | --- |
| 首页星空发光风格与工作台联系弱 | 首页与工作台共享字体、强调色、圆角和光谱图形语言 | 从首页进入工作台时具有连续的产品识别 |
| 新对话仍有“小惊喜、写作、收集”等通用入口 | 换成上传数据、选择数据集、使用模型三个业务入口 | 用户不用先理解命令即可开始已有流程 |
| 资源卡片大、原文件与时间信息突出 | 名称、分析目标、数据规模或评价摘要优先；文件元信息次级 | 典型 1440×900 窗口能完整浏览首行资源并操作 |
| 技术标识成为模型主标题 | 优先使用已记录的目标与算法形成显示标题；原标识可查 | 用户能识别模型用途，版本身份保持准确 |
| 侧栏混有长串近似的历史对话标题 | 功能导航分组；最近对话缩短并提供完整列表入口 | 资源导航稳定，历史记录不占满侧栏 |
| 建模侧栏包含多层切换与大量细节 | 侧栏负责摘要与最近进展；完整页承担详细分析 | 不必在窄侧栏中阅读双图和完整参数 |
| 边框、卡片和提示重复包裹内容 | 用间距、标题、分隔线组织层级 | 每个内容区通常只有一层面板边界 |

### 1.2 实施边界

第一轮以展示和交互组织调整为主，复用已有路由、API、权限校验、缓存和持久状态。数据解析、样本角色编辑、区间选择、模型挂载、轮次图、诊断和下载均继续可达。

以下业务约束贯穿改版：

- 浏览、切换、展开、缩放与刷新均不能触发模型调用、训练、重新预测、Test 评价或注册。
- “在新对话中使用”只挂载资源；真正执行仍由用户发送消息触发。
- 保留 Dataset、输入哈希、Profile、模型版本与实验身份绑定；显示名称不参与资源寻址。
- 历史缺失保持缺失；读取失败、未记录、损坏或身份不一致分别处理，不能展示其他记录补位。
- 建模中的 Cal、Cal CV、Val 与最终 Test 的指标不混用；后端确认完成后才展示对应最终结果。
- 模型主动停止、资源终止、失败、等待回复、最终保留和审批状态保持各自含义。界面收纳细节不能改变或隐藏实际异常。
- 保存模型保留当前真实用户授权流程；本设计不增加自动注册，也不改变已有审批规则。
- 所有示意内容仅用于布局说明；实现时读取真实记录。新增持久字段须另做契约评审。

### 1.3 功能优先与无删减验收

开发前建立需求台账，以用户此前明确要求、工作区说明、已维护的产品文档和当前实现为核对来源。以下为最低核验范围，不能用本表替代完整历史要求。每一项记录原始要求、当前入口、实现状态、验收用例、证据与改版后入口；状态区分“已验证”“待验证”“有缺口”，不能把旧部署说明或设计示意当作本次通过证据。

| 核验范围 | 必须保留或先补齐的内容 |
| --- | --- |
| 品牌与中文 | ChemAgent 公共身份、中文首次访问、显式语言偏好、登录/设置/文档中文化 |
| 数据集库 | CSV/TXT/MAT 本地上传、命名与搜索、用途分类、概览、跨会话复用 |
| 可视化解析 | MAT 结构/目标/轴、表格方向与列、预览确认、解析版本和高级设置 |
| 数据工作台 | 只读原值、样本表与光谱、角色编辑、跨页选择、区间选择、保存及离开保护 |
| 分区与数据身份 | 全未分配时已有自动划分；显式用途成员固定；完整赋值检查；文件哈希/Profile 绑定 |
| 模型库 | 正确保存、卡片/详情、准确版本、来源数据关联、维度、冻结训练数据预览 |
| 资源挂载 | Dataset 与精确 Model 版本的一键挂载、失败重试、保留附件、手动发送才执行 |
| 建模工作流 | 既有自主方案、模型选择、预算与停止规则、durable 等待问题、失败后的结果保留 |
| 节点完整信息 | 按实际执行顺序的方法、固定/搜索/最终参数、所有已记录范围指标、LLM 下一步原始建议 |
| 轮次与流程图 | 全部已接受决策、待执行/成功/失败/停止状态、真实反馈/保留关系、选择与重入恢复 |
| 图表与诊断 | 中文图表、原始/处理后谱、预测与残差、样本联动、缩放和历史缺失提示 |
| 结果与交付 | 最终保留方案、已完成的最终 Test、报告/模型/ZIP、原 Artifact 与下载权限 |
| 保存审批 | 当前真实用户授权、正确中文同意识别、精确产物入库；不得重训旧结果以完成保存 |
| 方法库 | 科学分类、适用条件、参数、限制与来源、管理权限及既有设置入口 |
| 兼容与持久化 | 历史会话、协议/存储标识、当前配置、已有数据与旧资源可读性 |

发现缺口时先完成必要实现与验证；未核验项继续列为未核验，不能以“页面更清爽”为由略过。实现可以调整入口、折叠次要信息，但每个原功能须有明确的新位置；方法、参数、指标、下一步建议不能仅存在于原始 JSON 或下载文件中。

本次实施已建立下述需求与入口台账，并运行对应回归。历史缺失与隔离验收边界在实施记录中单列；不把旧部署说明当作本次通过证据。

## 2. 信息架构与主要用户路径

### 2.1 沿用现有页面

```text
首页 /
└─ 工作区 /workspace → 新对话
   ├─ 新对话 /workspace/chats/new
   ├─ 对话列表 /workspace/chats
   ├─ 对话详情 /workspace/chats/[thread_id]
   │  ├─ 建模摘要侧栏
   │  └─ 完整建模过程 /workspace/nir/process/[thread_id]
   ├─ 数据集库 /workspace/nir/datasets
   │  └─ 数据集工作台 /workspace/nir/datasets/[dataset_id]
   ├─ 模型库 /workspace/nir/models
   │  └─ 模型详情 /workspace/nir/models/[model_id]/[version]
   ├─ 方法库 /workspace/methods
   └─ 设置与帮助（沿用现有入口）
```

不为了视觉改版新增“任务中心”或第二套资源导航。将侧栏菜单“光谱数据集库”简化为“数据集库”，页面副标题说明光谱用途。模型库、方法库和现有开关控制保持一致。

### 2.2 三条主要路径

1. 新数据建模：新对话 → 添加文件或选择已有数据集 → 用户说明目标并发送 → 查看进展 → 阅读结果与报告 → 按原流程授权保存。
2. 数据准备：数据集库 → 工作台检查样本与光谱 → 编辑用途/区间或解析设置 → 保存版本 → 在新对话中使用 → 用户发送任务。
3. 复用模型：模型库 → 查看模型适用信息与评价 → 在新对话中使用 → 添加待预测文件 → 用户发送预测请求。

快捷入口分别接入现有文件选择、`/datasets`、`/models` 的能力。按钮不创建新执行协议，也不发送隐藏提示词。

## 3. 视觉规范

### 3.1 颜色与表面

以下是建议基准值。实现时先映射为语义变量，统一验证对比度，避免组件内散落色值。

| 页面底色 | `#F7F8FA` | `#11181F` | 工作区背景 |
| 内容面板 | `#FFFFFF` | `#182129` | 卡片、对话框、菜单 |
| 次级表面 | `#EEF2F5` | `#22303B` | 工具栏、只读摘要 |
| 主文字 | `#17212B` | `#E8EEF3` | 标题、正文、关键数值 |

| 结构分隔 | `#E2E8EE` | `#334350` | 分隔线、面板边界 |
| 交互强调 | `#0F766E` | `#5ED4C7` | 主按钮、当前项、焦点 |
| 强调面上的文字 | `#FFFFFF` | `#10211E` | 实心强调按钮文字 |

图表继续使用 `core/nir/chart-theme.ts` 作为唯一颜色来源；本轮不随意重新分配原始谱、处理后谱、参考线、保留方案等语义。红色实测=预测参考线仍保留。UI 状态色与图表数据色独立管理。

深色图表需核查轴、网格、点和参考线的对比度；若扩展图表主题，仍在既有主题模块集中定义。下载报告可保留白底，不把屏幕深色样式直接写入报告。

### 3.2 字体与排版

| 场景 | 建议字号 / 行高 | 字重 |
| --- | --- | --- |
| 首页主标题 | 40–48 / 1.25；窄屏 30–32 | 600 |
| 工作区页面标题 | 24 / 1.35 | 600 |
| 欢迎标题 | 28 / 1.4 | 600 |
| 内容区标题 | 18 / 1.5 | 600 |
| 卡片标题 | 16 / 1.5 | 600 |
| 正文与操作 | 14 / 1.6 | 400–500 |
| 表格 | 13–14 / 1.5 | 400 |
| 元信息 | 12 / 1.5 | 400 |
| 主指标数值 | 24 / 1.2 | 600，等宽数字 |

中文系统无衬线字体优先：系统 UI → PingFang SC → Microsoft YaHei → Noto Sans SC → sans-serif。产品名与页面标题使用同一字体体系；代码、ID、哈希单独使用等宽字体。无需为改版增加远程字体依赖。

长名称在列表中最多两行；详情中允许完整换行。可截断的按钮或链接提供完整名称的可访问提示。技术标识可复制，不能只在悬停时可见。

### 3.3 间距、形状与层级

- 基础间距序列：4、8、12、16、24、32、48px。
- 页面左右留白：常规 32px，窄窗口 16px；区块间距 24–32px；面板内边距 20–24px，紧凑内容 16px。
- 控件高 36px，主要输入框 40px；触屏有效点击区域至少 44px。
- 面板圆角 12px，输入框/按钮 8px，短状态标签可用胶囊。避免每层容器都增加圆角和边框。
- 常规面板以浅边框区分；悬浮菜单和对话框使用阴影。资源 hover 可有轻微边框变化，不跳动、不持续发光。
- 同一工具栏仅一个最高强调操作。重复资源卡片的使用入口采用次级样式，hover/选中时增强；不要整屏出现大量实心按钮。
- 层级顺序：页面与当前状态 → 核心数据/图表 → 操作 → 文件与版本 → 完整技术记录。
- 动效只用于 120–180ms 的状态转换，尊重减少动态效果设置。首页去掉持续星空运动、标题旋转或循环闪光。

### 3.4 布局与窗口适配

| 区域 | 常规布局 | 收窄规则 |
| --- | --- | --- |
| 侧栏 | 240px，可折叠至 64px；顶部固定品牌/新对话 | 视口 <1024px 默认折叠；<768px 使用抽屉导航 |
| 顶栏 | 56px，面包屑+局部操作 | 长面包屑折叠中间项，保留当前页 |
| 资源页 | 内容最大宽 1280px | 依据剩余内容宽度排卡片，不仅依据整屏宽度 |
| 阅读型详情页 | 内容最大宽 1120px | 低于双列所需宽度时图表单列 |
| 数据工作台/建模过程 | 使用剩余可用宽度，宽屏上限约 1600px | 保证图、表可读；先折叠辅助区域 |
| 新对话输入区 | 680–760px，最大不超容器 | 小屏占满可用宽度 |

模型卡片最小约 280px，优先三列；数据集卡片最小约 360px，优先两列。可用内容区分别不足约 880px、744px 时减少列数。详情双图要求单图含轴标签至少约 360px，低于该条件改为上下排列。

关键验收尺寸：1440×900、1280×800、1024×768、768×1024、390×844。320px 做溢出兜底；移动端不新增专门流程。表格和图画布可有局部滚动，整页不能出现横向溢出。操作栏换行时不挤压标题到不可读。

## 4. 应用外壳与对话界面

### 4.1 侧栏

顺序为品牌、新对话、对话、资源分组、最近对话、底部设置与帮助。资源分组包含数据集库、模型库、方法库；不显示管理权限外的编辑入口。

最近对话常规展示 6–8 条，每条一行，当前项浅强调底；完整标题可通过可访问提示查看。“查看全部对话”进入已有对话列表。折叠侧栏保留带标签提示的图标。底部入口固定，列表独立滚动。完整对话列表继续提供已有功能。

### 4.2 新对话欢迎界面

标题建议：“开始一次光谱分析”。说明：“上传光谱数据，或选择已有数据集与模型，告诉我你想分析什么。”

```text
┌ 侧栏 ──────────┬────────────────────────────────────────┐
│ ChemAgent       │                                        │
│ + 新对话        │           开始一次光谱分析               │
│ 对话            │       一句简短说明                     │
│ 资源            │  ┌ 输入任务、已选文件或已挂载资源 ────┐ │
│   数据集库      │  │                                    │ │
│   模型库        │  │ 附件  思考/模型设置           发送  │ │
│   方法库        │  └────────────────────────────────────┘ │
│ 最近对话        │   上传数据  选择数据集  使用已有模型      │
│ …               │                                        │
│ 设置与帮助      │                                        │
└─────────────────┴────────────────────────────────────────┘
```

- 去掉通用主题按钮；知识问答仍可通过输入框自然进行。
- 三个业务入口接现有能力；库未启用时不出现无效入口。上传入口调用原有文件选择，不提前保存或执行。
- 主区域略高于垂直中心，减少空旷感；不用新增多组能力卡片填满页面。
- 文件或模型被选中后，在输入框上方统一展示资源条：名称、类型、移除；完整技术版本进入展开详情。
- 选择资源的失败提示贴近资源条，保留草稿与现有附件。仅显示已经证实的挂载状态。
- Tokens 信息归入现有用量详情，不作为欢迎页视觉焦点。保留当前思考和提供者模型设置。

### 4.3 已有对话与交付结果

- 正文宽约 760–880px，中文行高 1.65；长表格/图表可以更宽，不能缩到不可读。
- 工具步骤默认收纳为“已完成 N 个步骤”或当前执行说明；原始工具名、调用量等在展开区查阅。
- 确认完成的交付以一个结果摘要为主：真实状态、同一评价范围的 2–3 个指标、报告/下载入口、下一步。
- 交付文件沿用现有可信 Artifact 列表与折叠逻辑，避免在新的卡片中再复制所有下载项。
- 等待用户回复时，将实际问题靠近输入框清晰展示；任何导航或刷新都不能代替回复。
- 审批选择使用已有合法入口或真实用户回复，不新增模拟批准按钮。

### 7.2.2 画布、节点与连接规则

- 节点卡片包含步骤/轮次、实际状态、方法或动作摘要、同范围一项主指标；失败/待回复显示实际原因，不塞完整参数表。
- 竖向主路径表示有记录的阶段流转。搜索轮次之间的反馈线继续绑定 `base_experiment_id`；最终保留的回指线单独标注，不能把时间相邻自动解释为反馈或保留关系。
- 阶段顺序未知时分组展示孤立节点，不为追求图形连续补画执行关系。用户分支与循环仅来自真实记录；不能画未执行的算法比较分支。
- 支持画布平移、滚轮/按钮缩放、适配概览、定位当前/选中节点。默认保持节点文字可读，不能把长历史全部缩成小字。
- 顶部四个阶段定位入口只滚动/平移到对应节点，不过滤掉其他步骤；提供“已记录 X 个步骤”的全量可见计数和分页加载状态。
- 点击节点只改变选中与详情；方法、参数、指标、LLM 下一步建议按相同记录身份同步更新。手动选择历史节点后，新进展不抢占。
- 当前执行、已选中、最终保留、最低验证误差使用不同文字/边界说明，颜色不承担唯一含义。
- 窄屏点击节点后在画布下方显示同一详情，保留节点定位；键盘可通过等价节点列表完成选择。

### 7.3 节点必备信息与指标边界

| 节点详情分区 | 必须展示的内容 | 缺失/异常处理 |
| --- | --- | --- |
| 使用的方法 | 当前步骤的实际工具或处理动作；建模步骤展示有序预处理链、波长选择（若有）、模型算法；计划另标识 | 未执行时写“计划方案”，不能当成已使用方法 |
| 使用的参数 | 各方法固定参数、显式搜索网格、最终拟合参数；比较依据只用已记录内容 | 某参数未记录时就地说明，不能从别轮复制或猜测 |
| 结果指标与诊断 | 建模节点展示该轮所有已记录指标与范围、样本数、单位及诊断；解析/保存等节点展示实际产出与检查结果 | 不产生模型评价的步骤明确“不适用”；待执行/失败无结果说明原因，不伪造数值 |
| LLM 下一步建议 | 下一动作、拟用方法与模型、固定/搜索参数、建议依据、预期改善、对应下一节点与其执行状态 | 等待提案、未记录、流程已结束分别说明；不另调模型补写 |

点击任一节点，四类信息都必须保留，并通过固定的“概览 / 参数 / 诊断图 / LLM 建议”主分区直接查看。概览给出方法、结果和下一步摘要；参数与完整建议是显式主入口，不能收进“更多技术信息”。标题、方法摘要和关键指标固定展示；长参数表和原记录在其分区内部展开，不要求跳转另一页面。

LLM 建议、系统自动推进、用户确认三者分开标注。没有模型参与的步骤可以显示已记录的流程下一动作，但不能将其冒充 LLM 建议；流程结束后明确“本流程已结束，无下一轮建议”。

“最终指标”有两个层级，均须完整保留：

1. 每一轮执行结束后保存的最终评价结果，按 Cal、Cal CV、Val 分范围显示。不同范围不拼成同一组，已有 R²、RMSE、RPD、偏差等不能因只留两个大数而被删除。
2. 最终保留模型完成独立 Test 后的最终结果，在“最终结果”区以及对应已验证终态入口查看。不得提前打开 Test，也不能将其填入各个搜索轮次充当本轮指标。

除原始数值和范围，保留指标解释、全量/显示样本量、实际单位以及旧记录缺失说明。没有完成最终评价时明确标注“尚未完成最终评价”。

### 7.4 轮次、建议和科学含义

- 默认流程图；时间线作为辅助。节点卡显示轮次、动作、状态、方法摘要和同范围一项主要指标；点击后展示完整的四类信息。
- 图关系仍只来自记录，保留当前节点及相邻节点的默认聚焦；提供重置视图和键盘可用的节点列表。
- “最低验证误差”“最终保留”“最后执行”分别标识。不能因为数值最小就替换后端保留决定。
- 方法、参数、指标、下一步建议保留在同一个节点详情的固定主分区中；分区容器等高，决策依据与图表放对应位置。禁止用一个误差数值和概括文字替代完整结果，也禁止把所有内容展开为一条无限长的右栏。
- 执行前建议独立标注“下一轮已记录建议”，包含原始提案的处理链、固定参数、搜索范围、依据和预期。后续执行成功/失败另行显示。
- 选择历史轮次后不随新结果跳走；URL 保持已有 session、decision、layout 恢复能力。
- 失败、待执行或缺失记录保留区别，只有成功且身份匹配的结果才展示指标。阅读旧方案不得生成新建议。

### 7.5 图表规范

- 图表是节点详情的正式主分区。有合法预测/残差证据时，“预测诊断”同时直接画出实测—预测与残差，不让用户在这两图中二选一，也不收进技术详情。首次进入实验节点默认打开诊断图；参数、光谱对照和 LLM 建议的入口固定可见。
- 图表标题采用用户语言：“实测与预测”“残差分布/残差诊断”“原始与处理后光谱”；范围和样本数与标题紧邻。
- 单图常规高度 320–400px；放大视图约 440–560px。小屏增加纵向空间以容纳轴标签。
- R² 最多四位小数；误差沿用统一数值格式器，根据量级与单位保留足够有效数字；极小值用科学计数法，避免四舍五入成 0。显示精度变化不改变存储或报告数值。
- 单位未知时不标默认百分比或 nm；无真实轴时使用“光谱变量序号”。
- 诊断散点使用较小实心点；同图颜色对应范围或样本的真实语义，不给每个点装饰性配色。
- 保留实际参考线、零残差线、原始/处理后图例，网格浅灰；每图最多保留必要的刻度和一组简短图例。
- 散点、残差与表格继续联动相同样本；选中状态同时使用描边/文本，不仅依赖颜色。
- 工具条放大、缩放、复位和下载入口收纳在标题右侧；只有确实支持的功能才显示。
- 有抽样时紧邻图表说明“显示 X / Y 个样本；指标基于全量评价”。不能根据当前显示点重算整组指标。
- 历史缺失写“该次运行未记录图表”，提供现有指标；加载失败提供“重试读取”。两者不可共用含混空白。
- 最终 Test 图只在最终结果区展示；轮次中的可选范围限于既有 Cal/Cal CV/Val。

### 7.6 各步骤必须检查的图表清单

| 节点/场景 | 有对应数据时直接绘制 | 数据及展示约束 |
| --- | --- | --- |
| 数据解析与概览 | 光谱概览、目标分布、缺失情况等有科学意义的分布 | 只用既有合法概览聚合；未知轴用变量序号，不补造目标或单位 |
| 分区与搜索准备 | 各样本用途数量柱状图/条形图 | 数量来自真实用途配置；不读取封存 Test 原始值 |
| 实际预处理 | 原始与处理后光谱对照 | 同一实验、同一批可比样本和轴；沿用已记录 Cal 缓存，不在浏览时重新处理 |
| 每个成功实验轮次 | 实测—预测散点图 + 残差诊断图 | 默认相同范围并同步选中样本；每个可用 Cal/Cal CV/Val 范围都能查看对应图 |
| 参数搜索 | 候选参数与分数的曲线、点图或二维热图 | 必须有已记录候选得分；不同范围/比较组不混合，未运行网格点保持缺失 |
| 波长选择 | 已选波段覆盖或对应变量选择图 | 使用真实已保存选择结果；不能据模型名称推断波段 |
| 停止/保留与跨轮比较 | 同范围可比较指标的轮次趋势；明确标记最终保留 | 最低误差不自动替换保留模型；失败/待执行轮次不接成虚假成功曲线 |
| 最终 Test | 最终实测—预测散点图 + 最终残差图 | 仅完成后读取原有最终预测/诊断缓存；不重新评价或把结果用于搜索 |
| 分类任务（若该工作流实际支持） | 混淆矩阵、已记录的逐类指标等 | 需要已有或补齐受控投影的真实类别/统计数据，不把回归图强加到分类结果 |
| 其他已实现诊断 | 如真实记录的 PCA 得分、漂移、候选比较图 | 先确认已有能力、数据身份与边界；不为装饰在查看时新增计算 |

审批、文件完整性等没有适当连续/分布数据的步骤，用清楚的状态和回执表达，避免把真假状态包装成没有解释价值的饼图。所有实际可画且有意义的记录都应检查并绘制，不能只完成本表中的两张图就忽略其余已有证据。

绘图实现要求：

1. 先核验每类图的现有缓存/接口字段。若新运行缺少应有的证据，先在原执行链中补齐有界记录与 owner-scoped 读取投影，再开发图表；不得通过浏览页面重新训练、预测、PCA 或开启 Test 来补图。
2. 选择节点后，方法、参数、数值指标、图表和下一步建议一起切换，绑定相同 session/decision/experiment；旧响应不能注入另一个节点。
3. 详情宽度足够时散点与残差并排，紧凑预览每图至少约 260px，保持文字可读并提供放大；完整图优先约 520px。不足时在同一固定高度分区内上下排列。光谱对照、搜索图和趋势按图组组织，不同时堆成超长右栏，也不移到全局页面底部。
4. 图上选中样本在散点、残差及已有表格中同步；同时提供可键盘使用的样本选择方式。显示相同短样本 ID、真实/预测值、残差与单位。
5. 加载中显示图形骨架；加载失败允许重试读取；历史未记录明确说明；不适用说明原因。不能把接口失败当成“历史无图”，也不能用其他轮次的点填满空白。
6. 新执行必须记录其已实现图表所需证据。存在应有数据却只有“查看诊断”文字、静态图标或空占位时，本项验收不通过。旧记录原本未保存的限制单列为历史限制，不追溯重算。

## 8. 方法库、首页与帮助

### 8.1 方法库

沿用统一页头、搜索、分类筛选与卡片间距。卡片只显示方法名称、类型、一句用途、可核验的提供者；完整参数、适用条件、限制与来源放详情。

预处理方法、回归模型和其他工具维持已有科学分类。浏览详情不执行方法，文献参考不等于系统已采用；管理功能继续留在设置中，并受原权限控制。

### 8.2 对外首页

采用与工作台一致的字体与青绿色强调。首屏使用浅中性背景、简短标题和静态光谱图形，不持续播放星空与粒子。

建议结构：

1. 顶部：ChemAgent、使用文档、进入工作台；项目/开发者链接放次级位置。
2. 首屏：“近红外分析，从数据到模型”；两行说明；主按钮“进入工作台”，次链接“查看使用指南”。
3. 三步流程：准备数据 → 建模与诊断 → 复用模型预测。每步只写一个用户能理解的收益。
4. 一组核心能力：数据解析、建模诊断、模型复用，配简洁界面示意。
5. 简短来源与评价说明、文档和项目入口。

避免重复多组相近的“核心能力/完整流程/分析引擎/平台能力”。确定性工具、哈希和审计等深层解释放文档，首页保留用户作决定需要的信息。展示示例时标注“界面示意”，不能伪装成真实用户或在线运行成绩。

登录/设置页共用静态光谱背景、品牌排版与按钮；保留已有中文默认和显式语言偏好。

### 8.3 中文文案

| 当前/技术用语 | 面向普通使用者的表达 |
| --- | --- |
| 挂载到对话 | 在新对话中使用 |
| Profile | 解析版本（技术详情保留 Profile ID） |
| Cal / Val / Test | 训练集 / 验证集 / 测试集，首次或详情附原范围 |
| Cal CV / OOF | 训练集交叉验证（折外预测） |
| LLM 自主建模 | 自主建模 |
| 结构化工作流证据 | 已记录的建模过程 |

“训练集”对应当前产品 Cal 的用户标签，不能把 Cal CV 均值、折外评价和校准拟合合并。高级技术术语在需要时保留，科学意义不因中文化改变。

## 9. 通用状态与交互规格

| 状态 | 展示规则 | 可用操作 |
| --- | --- | --- |
| 首次读取 | 与最终布局相近的骨架；每页一个读取说明 | 导航、取消/离开 |
| 空资源库 | 一句说明+合适入口；不放空统计图 | 数据集上传；模型库返回对话说明保存来源 |
| 搜索无结果 | 显示关键词相关提示 | 清除搜索；保持已选分类 |

统一约定：

- 导航用链接，状态切换用按钮，更多操作用菜单。不要整张卡片套链接后再放交互按钮。
- Toast 用于保存成功、复制完成等短反馈；持续问题留在对应区域，不用一闪而过的提示代替。
- 请求期间避免重复提交；失败保留用户草稿、筛选、文件和选中资源。
- `aria-live` 只播报必要状态；错误使用 alert；页签、焦点、菜单和抽屉支持键盘。
- 正文对比度至少 4.5:1；必要大文字和非文字控件边界至少 3:1。普通装饰分隔线不承担交互识别。
- 焦点环清晰可见，尤其避免沿用透明 ring 使键盘焦点消失。既有自动生成 UI 基元保持不手改，优先通过主题变量、使用处属性或组合组件处理。
- 整体最多页面与一个局部数据容器两层可滚动区域；避免侧栏套列表套卡片各自独立滚动。

## 11. 实施顺序与开发任务

### 阶段 0：先核对原有要求并补齐功能

交付：完整需求台账、功能入口映射、已验证证据和缺口清单。按 1.3 核验最低范围，再补齐此前其他明确要求。

任务：读取当前实际版本与已有用例 → 核对原要求和入口 → 用隔离数据及历史只读记录验证 → 先修复缺失或退化能力 → 建立改版前功能基线。

完成条件：原有明确要求逐项有实现与验收；未验证项不能标为完成；不存在以简化界面为理由的删减。美化阶段每次改动都对照该基线回归。

### 阶段 A：统一基础样式与外壳

交付：颜色/字体/尺寸 token，侧栏与通用页头，通用状态，中文操作命名。

任务：明确浅色与深色变量映射 → 检查通用按钮/输入焦点 → 调整侧栏与最近列表 → 选择数据集库、模型库两页验证公共组合组件。

完成条件：关键尺寸无全局横向溢出；深浅主题文字/焦点可读；导航、菜单与 feature flag 不变。

### 阶段 B：新对话与资源库

交付：三个业务入口、统一资源条、紧凑 Dataset/Model 卡片、搜索与空态。

任务：接入既有选择入口 → 收纳次级操作 → 标题和元信息层级 → 模型显示回退 → 检查挂载错误与重试。

完成条件：用户可完成上传、选择已有数据、选择模型；选择动作不启动运行；所有原有资源入口可达。

### 阶段 C：数据工作台与模型详情

交付：数据页签、靠近图的波段设置、批量用途栏、模型范围切换与宽图、来源版本区。

完成条件：草稿/保存/离开保护、样本用途、真实轴、精确模型版本、冻结 Profile、指标范围和旧模型缺失状态均保持。

### 阶段 D：建模摘要与完整过程

交付：覆盖数据进入到模型保存的纵向全过程画布、缩放/阶段定位、同步节点列表、完整节点详情及其应有图表、摘要侧栏、下一轮原始建议、最终结果区。

完成条件：每个节点都能查看方法、参数、完整范围指标和 LLM 下一步建议；历史选择可恢复；新数据不夺取当前选中；建议与执行分离；无新增调用/训练/Test/注册；全部证据继续精确绑定。信息缺失不算通过，只能按真实缺失状态验收并记录历史限制。

### 阶段 E：首页、方法库与帮助一致性

交付：统一首页和登录视觉，方法库卡片/详情一致性，文档截图与入口文案更新。

完成条件：中文首次访问、英文可选与偏好持久化正常；静态模式、文档和文章路由正常；生产构建无误。

独立可选任务：自定义模型显示名称、持久化资源视图偏好、额外对比能力。只在有明确需求时开展，不能混入第一轮视觉改版扩张范围。

## 12. 验收与开发交接清单

### 12.1 视觉与交互验收

- 1440×900 下，资源页首屏能看到标题、搜索/分类和一整行可操作卡片。
- 新对话三个入口与主要用户路径一致，没有遗留通用主题入口。
- 页面主操作清楚；资源列表没有重复大面积实心按钮；次级操作可通过菜单和键盘发现。
- 一个内容面板不再层层套三层以上边框；长名称与中英文混排不挤坏布局。
- 建模过程左右工作区顶底对齐；选中第一轮、最后一轮、长参数或长建议时外框不被撑长。右侧固定主分区入口可见，图表分组不删除任何图。
- 每张图的轴、范围、单位、样本数可读；双图不足宽度时自动单列。
- 浅色、深色、200% 浏览器缩放与减少动态效果设置可用；键盘可完成所有主要流程。
- 空库、无结果、读取失败、未记录、身份校验失败有各自清晰状态。

### 12.2 业务回归重点

3. Dataset/Model 挂载到新对话；挂载后无自动消息、训练或预测。
