# 模型按训练数据集分组：第一阶段

模型库默认按已验证的训练数据集编号分组，支持组内目标筛选、全局目标/分析类型/算法/质量标记筛选及全部模型视图。组内使用紧凑列表，保留训练 Profile 链接、精确模型版本报告和新对话挂载入口。分组折叠在当前页面切换视图和筛选时保持；排序依据保存时间，不依据 Test 指标。

数据集库增加关联模型数量及筛选跳转。两页共用用户隔离的查询，旧模型仅通过现有报告接口尝试恢复来源，且必须匹配模型文件和训练数据哈希。最多三个并发报告读取；失败保留模型，来源未知不会按文件名猜测。后端补充旧版建模记录的只读关联恢复，不改动历史数据库关联、模型包或审批。

验证：

- 前端检查通过，消息组件原有两条 Hook 警告保持。
- 80 个单元测试文件、637 项测试通过。
- 模型库 7 项、数据集库 8 项、模型挂载 6 项浏览器回归通过。覆盖同名不同身份、不同训练版本、多目标筛选、历史关联恢复、哈希不符拒绝恢复、数据集跳转和精确版本挂载。
- 数据集上传测试原先在首屏交互尚未就绪时点击；现在等待数据卡片加载完成，并补齐新增模型查询的模拟响应。
- Docker 真实登录页面验证列表/空结果筛选/详情/数据集筛选跳转。旧路由缓存已移出前端目录并重新生成，详情页正常。
- 初次验证时，两条旧 PLS 模型显示“训练数据来源待确认”，原因是恢复逻辑只覆盖自主建模会话，没有覆盖旧版 `nir_analyze`，并非缺乏原始数据证据。后续核实两条模型已保存的输入文件哈希均与 `real-tablets-nir-acceptance` 的实际源文件一致。
- 未重新训练用户模型、未调用付费提供者、未重新评价用户模型的 Test。本报告随功能修改一并存档。
