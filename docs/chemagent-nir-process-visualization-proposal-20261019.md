# ChemAgent 近红外建模过程可视化完整方案

日期：2026-10-19  
状态：设计提案，尚未实施。本次仅整理方案，不修改产品代码、建模规则或运行中的任务。

## 1. 页面要解决的问题

用户进入建模过程页后，应能沿着同一条线理解：

**用了什么数据 → 数据怎样进入建模 → 每轮改变了什么 → 结果为什么变化 → 接下来怎么优化 → 为什么保留这个模型 → 最终交付了什么。**

设计重点是让数据、实验、图表和决策互相对应，减少用户在流程图、图表页和聊天记录之间查找的次数。

本期以现有单目标定量建模流程为主。分类、校正迁移等任务以后复用页面框架，但使用各自的专属指标和图表，不把回归结果模板直接套用过去。

## 2. 整体页面布局

采用“顶部任务摘要 + 左侧阶段导航 + 右侧阶段详情”的结构。

| 位置 | 主要内容 | 设计要求 |
| --- | --- | --- |
| 顶部导航 | 工作区 › 建模过程、原对话标题、返回对话 | 工作区继续返回当前过程所属的原对话；直接打开、刷新也一致 |
| 任务摘要 | 数据名称、目标、当前阶段、已完成实验数、保留轮次、当前需要处理的事项 | 压缩为两行左右；资源和技术细节折叠 |
| 一级切换 | 建模过程／最终结果与交付 | 各阶段图表放回对应详情中，避免再设一个重复的通用图表仓库 |
| 左侧约 28% | 数据准备、方案搜索、最终评价、交付与审批 | 默认按阶段分组，支持折叠、定位当前、定位保留轮次 |
| 右侧约 72% | 当前阶段的事实、图表、解释和下一步建议 | 内容随节点变化，不要求所有节点共用同一组标签 |
| 详情工具区 | 与上一轮比较、图表放大、返回对话补充要求 | 仅在当前内容适用时出现 |

任务状态和查看位置分开显示。例如，用户正在看第 1 轮时，顶部仍可显示“任务已完成，保留第 2 轮”，但不自动把用户切走。

默认使用清晰的阶段导航。现有轮次时间线、方案关系图作为辅助视图保留，切换后维持同一选中节点，不新增含义重复的导航。

## 3. 左侧流程如何改

节点只展示识别这一步所需的信息；详细参数和大段解释放右侧。

| 阶段／节点 | 左侧摘要 | 点击后右侧展示 |
| --- | --- | --- |
| 文件与数据来源 | 文件名、格式、记录状态 | 数据身份、来源和可用预览 |
| 数据解析与确认 | 样本数 × 变量数、目标名、是否确认 | 矩阵映射、方向、光谱轴、目标、质量检查 |
| 分区与搜索准备 | Cal／Val／Test 数量、Test 封存状态 | 固定分区、分组保护、验证协议 |
| 第 N 轮实验 | 模型、主要预处理、Val 指标、执行状态 | 本轮变化、实际方案、诊断、下一步建议 |
| 停止与保留 | 停止原因、实际保留轮次 | 决策依据、保留关系、未解决问题 |
| 冻结与最终评价 | 冻结／评价状态 | 最终模型绑定、已完成的最终评价 |
| 交付与审批 | 报告、模型文件、审批／入库状态 | 下载、使用说明、原有审批入口 |

“最低 Val RMSE”“LLM 已保留”“最后执行”使用独立标签，允许出现在不同轮次上。最低分标签不会替用户或模型选择最终方案。

顺序线只表达流程顺序。方案关系图只绘制已有记录证明的反馈来源和保留关系，不能根据显示先后猜测关系，也不能添加虚构分支。

## 4. 数据准备详情：让用户看懂输入

### 4.1 数据概览

点击文件或数据来源节点后，先展示一张可读的数据说明卡：

- 文件名称、格式、大小、来源类型及已记录的导入时间。
- 本次使用的数据版本、解析版本和缩短的校验标识。
- 样本数、光谱变量数、当前分析目标及其单位。
- 光谱轴的类型、起止范围、方向和单位；缺少单位时明确显示“单位未记录”。
- 状态说明：解析完成、需要确认映射、来源关联未核实或历史记录缺失。

样本类型、仪器型号、采集条件等只展示真实记录。不能从文件名推断“这是药片数据”，也不能把变量序号自动写成波长 nm。

概览绑定本次实际使用的文件和解析版本。后续数据集更新，不改变这次历史任务的展示。

### 4.2 光谱与目标

默认先看图，再看表：

| 图表 | 用户操作 | 展示限制 |
| --- | --- | --- |
| 原始光谱叠加图 | 悬停查看样本、放大波段、突出某条曲线 | 标明可见分区、显示曲线数量及抽样情况 |
| 已保存的光谱统计图 | 切换已有均值或范围视图 | 只有已有对应统计记录时显示 |
| 目标值分布 | 查看已有的分布和统计摘要 | 明确目标单位、统计范围；不暴露封存 Test 分布 |
| 有界数据表 | 只读查看允许展示的样本和字段 | 分页／限量展示，不一次性渲染整张高维矩阵 |

在封存建模流程中，原始和处理后光谱以允许展示的 Cal 证据为基础。Test 在搜索阶段只展示封存状态和允许显示的分区元信息，不通过“文件预览”绕过封存。

独立数据集工作台继续遵循原有权限与版本规则；它的当前内容不自动成为这次历史实验的证据。

### 4.3 数据结构与解析

以可读表格展示“文件字段如何映射到建模输入”：

- 光谱矩阵来自哪个字段；MAT 可展示已确认的变量路径。
- 行和列分别代表什么，是否进行了已记录的转置。
- 目标字段、波长字段、样本编号和分组字段。
- 多个候选矩阵或多个目标产生的歧义，以及当前确认结果。

过程页默认只读。发现映射问题时，提供“返回对话说明问题”。需要纠正输入的场景走原有确认流程，不能在历史详情中悄悄改变已执行实验的数据。

### 4.4 数据质量

展示已记录的缺失值、无效值、重复、光谱轴异常和目标缺失等检查结果。每条说明包含：发现了什么、影响范围、流程实际如何处理。

“疑似异常”与“已确认错误”分开。高亮、筛选和圈选只是查看操作，不会删除样本或改变训练数据。没有检查记录时显示“未记录该检查”，不能写成“数据正常”。

## 5. 分区与验证协议详情

采用三张分区卡片或分段条展示：

- **Cal：**用于模型拟合；Cal CV 是在 Cal 内产生的交叉验证证据，不是额外的一份独立数据。
- **Val：**用于搜索和比较方案，已参与方案选择。
- **Test：**搜索期间封存，只在合法最终评价完成后展示已有最终结果。

并列显示已记录的划分方法、样本数、分组隔离约束、固定划分身份以及验证范围。

页面用短句解释“哪些结果用于选方案，哪些结果用于最终评价”。内部留出不能写成外部验证。

不在这里提供重新随机划分、修改预算或重启本次搜索的按钮。已完成任务也不因刷新页面产生新分区。

## 6. 每轮实验详情

右侧按以下顺序组织：

**本轮变化 → 实际方案 → 结果与诊断 → 下一步优化建议。**

顶部提供锚点导航；默认先显示变化摘要和关键结果。实际参数、搜索候选和完整决策记录可进一步展开。

### 6.1 本轮变化

用一句话说明本轮相对记录中的反馈来源改了什么，并显示对照表：

| 项目 | 对照轮次 | 当前轮次 |
| --- | --- | --- |
| 预处理 | 真实执行步骤 | 真实执行步骤 |
| 模型 | 实际模型 | 实际模型 |
| 参数／搜索范围 | 实际记录 | 实际记录 |
| 可比评价指标 | 同一范围的原始值 | 同一范围的原始值及变化 |

没有可比前序实验时显示“首轮实验”或说明不可比原因。不同划分或不同验证协议的分数不直接计算改善幅度。

### 6.2 实际方案

用横向管线显示“原始光谱 → 预处理步骤 → 可选波段选择 → 模型”，可点击查看每个实际执行步骤的说明与参数。

区分三类信息：

- 执行前提交的计划。
- 实际执行的配置与搜索范围。
- 搜索后得到的拟合参数和结果。

方法说明可以链接已有方法库及其来源，但方法说明不等于这次已采用，也不等于已验证有效。

### 6.3 预处理效果

同一批样本左右并排显示原始光谱和处理后光谱：

- 使用一致的样本颜色和选中状态，支持同步缩放光谱横轴。
- 各自保留正确纵轴、单位和范围，不强制处理前后的幅值相同。
- 标明当前轮次、数据分区、实际预处理步骤和抽样数量。
- 默认比较原始输入与整条管线输出。
- 中间步骤只有在执行时确实保存后才允许逐步切换；历史缺失时不补算。

实际执行过波段选择时，可叠加已保存的保留波段。图表高亮只表示查看，不修改波段方案；没有选波段记录就不展示“重要波长”。

### 6.4 模型表现与诊断

优先显示以下内容：

| 内容 | 用途与展示方式 |
| --- | --- |
| 指标卡 | 按 Cal、Cal CV、Val 分开，指标与图表范围一致 |
| 实测值－预测值散点图 | 展示预测与参考值的对应关系，保留参考线 |
| 残差图 | 明确本项目残差定义：预测值减实测值，显示零线 |
| 残差分布 | 有真实保存证据时展示 |
| 搜索候选表／曲线 | 展示实际候选、分数、失败状态及拟合参数 |
| 已保存的其他专属诊断 | PCA、载荷、距离等只在有合规证据时开放 |

Cal 拟合、Cal CV 折外预测和 Val 预测不能混在一张没有范围标签的图上。候选表中的折均值与折外点计算范围也要明确区分。

R²、RMSE、Bias、RPD 等只展示已返回的真实值及适用说明。不能把某个单独指标阈值画成通用于所有数据的“合格线”。

图表沿用有界证据：展示“总样本数／实际显示点数”，指标读取原始全量记录，不用显示点重算。散点和残差通过稳定样本标识联动；若与光谱没有可核实的对应关系，不强行联动。

光谱、预测散点和残差是本方案优先组织的图表类型，参考 [Chemotools 官方绘图分类](https://chemotools.org/methods/plotting_methods.html)。具体计算口径仍以 ChemAgent 当前证据契约为准。

## 7. 下一步优化建议放在哪里

分为“当前轮次的下一步”与“本次任务结束后的改进方向”，两者不能混淆。

### 7.1 每轮下一步建议：放在本轮诊断之后

右侧设置独立卡片，标题为“下一步优化建议”，默认展开。卡片展示大模型在下一次执行前实际提交并被接受的提案。

| 字段 | 要回答的问题 |
| --- | --- |
| 一句话方向 | 下一步准备解决什么 |
| 判断依据 | 根据本轮哪些已记录的结果作出判断 |
| 建议动作 | 调参、更换预处理、更换模型、探索其他方案或停止 |
| 具体方案 | 预处理、模型、固定参数和搜索范围 |
| 预期作用 | 希望改善什么；保留原提案的不确定性 |
| 后续状态 | 已提交待执行、执行中、已执行、执行失败或未执行 |
| 执行链接 | 跳转到真实后续轮次；失败时查看对应失败记录 |

完整阅读链条为：**本轮结果 → 下一步提案 → 后续实际执行 → 实际效果。**

不把后续拟合结果反写成事前建议，不根据结果倒推“模型当时为什么这样想”。建议没有预期效果或依据字段时保留缺失，不补写。

具体状态文案：

- 尚无下一条提案：“尚未记录下一步方案”；任务仍运行时补充“等待流程更新”。
- 已接受提案但尚未完成：“已提交下一步方案，尚无执行结果”。
- 已完成：“已在第 N 轮执行”，提供跳转。
- 已记录主动 STOP：“停止优化，保留第 N 轮”，展示实际停止依据。
- 资源终止、运行错误或用户停止：显示对应原因，不能写成模型主动认为无需优化。
- 等待用户回答：“等待你回复”，展示原问题并返回原对话；阅读页面不能解除等待。

自动建模仍由原有流程执行。此卡片不额外增加每轮手动批准按钮，也不通过页面访问调用大模型生成新建议。

### 7.2 顶部：显示当前下一步的短摘要

顶部只保留一句当前状态，例如“正在执行第 3 轮”“下一步方案已提交”“等待你确认目标字段”或“已停止，等待审批”。点击定位相关节点。

用户选择历史轮次时，该轮仍展示它当时的后续提案，顶部同时保留整个任务的最新状态。

### 7.3 最终页：后续改进方向

放在“最终表现与局限”之后、“下载与审批”之前。这里承接已有最终结论中真实记录的后续工作建议，说明建议针对什么问题，以及哪些事本次尚未验证。

每项标明“建议，尚未执行”。没有保存建议时显示未记录，不在打开最终页时额外生成。

后续新工作需要新的明确请求及合法执行入口；不能把已结束的搜索当作可无限恢复的任务。

## 8. 多轮比较

从轮次详情提供“比较轮次”入口，打开宽面板。默认比较当前轮与其真实反馈来源；用户可选择同一会话内的其他可比实验。

比较内容包括：

- 预处理、模型、参数和实际搜索范围的差异。
- 相同范围的指标对照。
- 使用相同样本身份时的预测和残差差异。
- 每轮的建议动作、执行结果和保留关系。

增加 Val 指标随轮次变化的趋势图，失败轮次保留状态，不伪造分数。被保留轮次和最低 Val 轮次分开标记。

不使用雷达图把不同单位、不同意义的指标压成一个“综合最佳分”。不可比的实验可并列查看事实，但不展示优劣排序或改善百分比。

## 9. 最终结果与交付

最终页按以下顺序阅读：

1. **最终结论：**实际保留了哪轮、当前完成到哪一步。
2. **最终方案：**冻结后的预处理、模型、参数和数据版本。
3. **最终评价：**范围、样本数、已有指标、预测与残差图。
4. **结论与局限：**已经完成的验证、尚未证明的能力。
5. **后续改进方向：**已有的未来建议，标明尚未执行。
6. **交付文件：**模型包、报告、ZIP 等真实发布的文件。
7. **审批与入库：**沿用当前明确授权流程，展示实际结果。

Test 仅在最终评价已完成后展示原始最终缓存。不得为查看页面再次预测、评价 Test 或重新训练。

“模型已保留”“已冻结”“最终评价完成”“文件发布完成”“用户已审批”“模型已入库”分别展示，不能合并成一个笼统的完成状态。

若训练成功但报告发布失败，页面保留训练与评价事实，并明确标注交付失败。若模型质量未达门槛但获得用户确认保存，沿用服务端真实质量状态和说明，不改写指标。

保存失败不显示已入库；功能未启用时不显示不能完成的入库操作。

## 10. 状态、缺失与异常展示

状态使用文字、图标和颜色共同表达，不能只靠颜色。

| 情况 | 推荐呈现 | 可用操作 |
| --- | --- | --- |
| 正在运行 | 当前步骤、最近一次已记录进展 | 查看当前记录 |
| 等待用户 | 原始问题、等待原因 | 返回原对话回答 |
| 历史未记录 | “本次运行未保存该项记录” | 查看仍可用的摘要 |
| 记录不可用／损坏 | “记录暂不可用”及有限原因 | 重试读取，不能重做实验 |
| 权限不足／会话不匹配 | 明确不能访问对应记录 | 返回原对话 |
| 主动停止并保留 | 保留轮次及原决策依据 | 查看最终方案 |
| 资源达到上限 | 真实资源终止说明 | 查看已有结果和实际保留状态 |
| 运行失败 | 失败阶段、简明原因、已完成部分 | 返回对话处理 |
| 用户停止 | 用户停止状态、已完成记录 | 查看已有结果 |

对于历史文件节点，“来源未单独记录”不能误写成“没有上传文件”。没有图表不代表训练失败，图表加载失败也不改变已经保存的科学指标。

重试读取只重复获取已存在的记录，不触发训练、模型调用或 Test 操作。

## 11. 视觉与交互规范

- 延续现有深色界面，以青绿色表示选中位置；成功、警告、失败有独立文字和图标。
- 指标字体和位置统一，同一指标在不同轮次使用一致显示精度，悬停可看完整记录值。
- 目标、波长和预测值显示已知单位；处理后光谱按实际变换标注纵轴。
- 单条曲线颜色跨关联图保持一致，非选中样本降低透明度，避免所有曲线同时高饱和显示。
- 右侧采用一个主要内容滚动区；普通图表不各自嵌入纵向滚动条。图表可放大，关闭后保留位置。
- 顶部摘要保持紧凑；参数、资源账目和完整记录按需展开。
- 同一页内保留选中节点、视图和详情位置；刷新后恢复，但不得跨会话套用。
- 流程更新不打断用户阅读历史记录；以“有新的执行记录”提示引导查看。
- 为键盘操作提供焦点、选中状态和可读标签；错误与缺失说明可被辅助工具读取。
- 历史分页、详情和图表按需加载；避免一次打开全部实验及大体量样本表。

## 12. 现有能力与新增工作的边界

以下是基于当前仓库说明整理的设计起点，不表示本方案已经实现或完成线上验收。

| 能力 | 当前基础 | 本方案需要的工作 |
| --- | --- | --- |
| 返回原对话 | 已有当前对话绑定的面包屑行为 | 保留并在新布局验收 |
| 生命周期／轮次／关系图 | 已有共用记录和导航 | 改善层级与节点摘要 |
| 每轮诊断 | 已有 Cal／Cal CV／Val 有界缓存和绑定 | 重新组织、统一标签与联动 |
| 原始／处理后光谱 | 已有实际 Cal 光谱缓存 | 提升入口和并排比较体验 |
| 下一轮建议 | 已有执行前提案、状态和后续链接 | 改为显眼卡片并贯通阅读顺序 |
| 数据集概览 | 已有数据集工作台及解析版本机制 | 核实过程级绑定、可见范围后复用 |
| 文件／解析阶段事实 | 部分历史缺少独立回执 | 明确缺失；新运行按需补充有界记录 |
| 中间预处理图、PCA 等 | 不保证每轮已保存 | 后续执行阶段新增合法采集；不在查看时计算 |
| 最终评价／下载／模型库 | 已有独立状态与受控接口 | 统一最终页的呈现和回链 |

如果某项新图需要当前没有的证据，先明确采集位置、样本范围、大小限制和绑定方式，再决定实施。不能仅靠前端拼出一张貌似完整的图。

## 13. 实施顺序

### 第一阶段：先让现有信息看得懂

范围：紧凑摘要、分阶段详情、节点摘要、每轮真实配置、现有光谱和诊断、显眼的下一步建议、诚实的缺失状态。

数据节点优先展示能够核实的身份、结构和已有预览；没有合规可用图时给出明确说明。

交付标准：用户不翻聊天记录，就能看懂本轮做了什么、结果怎样、下一步是什么，以及任务实际停在哪里。

### 第二阶段：让证据可以串起来

范围：精确数据版本关联、受控数据概览、样本联动、可比轮次对照、指标趋势、最终结果与后续建议整合。

交付标准：从文件到某轮实验再到最终模型，来源一致；从建议到实际后续执行，可以直接跳转核对。

### 第三阶段：补充有价值的深入诊断

范围：仅对新执行采集必要的中间预处理证据、已有波段选择解释及适用的专属模型诊断；完善图表导出与报告一致性。

交付标准：每项新增证据都有明确采集成本和用途，不增加为了页面展示而发生的训练或 Test 评价。

新一轮建模、额外模型调用或真实服务验收均属于后续明确授权范围。本提案不触发这些操作。

## 14. 验收场景

后续实施至少覆盖以下实际用户路径：

1. 从原对话进入、直接打开和刷新过程页，都能返回同一个原对话。
2. 点击文件能核实本次输入与版本；缺单位、缺来源或缺图时有对应解释。
3. 搜索期间看不到通过新入口泄露的 Test 曲线、目标分布或测试结果。
4. 切换轮次后，参数、光谱、诊断和下一步建议始终属于同一会话和对应实验。
5. 已提交但未执行的提案可见，且不展示虚构的执行分数。
6. 后续执行成功或失败后，原提案不被覆盖，执行状态与链接正确。
7. 最低 Val 轮次与实际保留轮次不同，也能正确展示。
8. 等待用户时返回原问题；页面刷新和读取不会解除等待或继续运行。
9. 主动 STOP、资源终止、用户停止和运行错误的文案与事实一致。
10. 历史无缓存或缓存损坏时，保留可用结果，不重新训练补图。
11. 最终 Test 图复用已完成的最终证据，下载与审批状态分别可核实。
12. 选中旧轮次时收到新结果，阅读位置与选择不被抢走。
13. 在真实 Docker 部署、已登录页面验证图表、返回导航、文件下载及数据版本；只测接口返回成功不算完成。
14. 图表显示点经过抽样时，全量指标保持不变，范围、单位和样本计数一致。

验收以页面真实行为和原始证据为准。离线夹具、接口拦截与真实提供者运行分别记录，不互相替代。
