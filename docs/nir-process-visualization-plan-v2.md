# ChemAgent 建模过程可视化改造方案（修订版）

日期：2026-10-04
用途：交给执行智能体实施的产品与工程方案。本文是待实现设计，不代表功能已经上线。
关系：保留 `nir-process-visualization-plan.md` 作为原稿；后续实施以本修订版为准。

## 1. 目标与问题定位

目标是让用户沿着一次数据集建模的真实过程，点击任一步骤，看懂“在做什么、输入是什么、怎样处理、得到什么、依据是什么”，并通过图表探索证据。

当前实现已经提供建模过程、选择依据和最终结果的摘要，但仍存在以下缺口：

| 当前问题 | 本次解决方式 |
|---|---|
| 阶段导航和图表主要承担结果展示，缺少步骤探索 | 增加独立过程页，每个步骤都有可点击节点、图表和解释 |
| 工作流摘要无法支撑完整光谱、样本诊断和候选详情 | 计算时生成结构化图表证据，按需加载 |
| 执行完成与图表可用混为一谈 | 分离执行状态、证据状态 |
| 跨尝试只按指标名、协议和验证范围比较 | 加入数据版本、实际划分、评估方式和指标定义的严格匹配 |
| 原始光谱与样本坐标的访问规则不明确 | 线程所有者可查看本线程已有权限的数据；受限会话按服务端能力降级 |
| 独立页面缺少持续刷新与版本一致性机制 | 摘要版本轮询、不可变图表引用、请求取消和缓存隔离 |
| 实施范围与验收范围不一致 | 先完成单目标定量闭环，再扩展其他任务；逐阶段验收 |

当前代码核对结果：`workflow.py` 的 history 限制为 50 条；`decision_facts.py` 会将列表裁到 8 项；`modeling.py` 存在将 `RMSE_tuning` 写入 `RMSECV` 的路径；现有 `useNIRWorkflow` 主要在聊天流缺失工作流时补读状态。这些结构可以复用作摘要，但不能直接视作完整过程记录、完整候选表或独立页面的实时数据源。

## 2. 产品范围与首期边界

首期交付一条真实的单目标定量建模闭环：数据解释与审查 → 数据划分 → 预处理 → 波长选择判断 → 模型比较 → 验证诊断 → 反思与重试记录 → 审批/注册状态。

首期支持已有单目标主训练路径实际产生的过程证据，优先选择内部留出协议贯通。每一步必须能解释；只有确实运行并记录的步骤才要求相应图表。波长选择被跳过时展示全谱保留原因，不能为了页面完整而额外运行算法。

本期交互是查看、筛选、缩放、联动和对比。选择图表区域、点击候选不会改变训练数据、替换模型或启动训练。修改参数后重新建模、删除异常样本等操作留待后续单独设计，并创建新的尝试。

分类、多目标、固定外部验证、校准迁移的专用图表放入后续阶段。首期遇到这些任务继续提供已有摘要和产物入口，明确提示该任务的过程图尚未接入。校准迁移始终是独立能力，不能作为普通预处理节点。

## 3. 页面与用户操作

保留聊天中的 NIR Sheet 作为速览入口，增加“查看完整建模过程”。独立页面的建议路由为 `/workspace/nir/process/{threadId}`，定位参数包括 `run`、`attempt`、`step`；最终文件位置沿用项目现有 App Router 组织方式。

桌面页面采用三栏结构：

```text
数据集 / 目标变量 / 任务状态 / 第几次尝试 / 证据更新时间
步骤导航              图表与结果                    本步说明
数据解释与审查        原始光谱、分布或质量摘要       目标与输入
数据划分              当前步骤的主图                实际方法与参数
预处理                对比、图例、缩放、重置         选择规则与依据
波长选择              联动明细表                    证据来源与下一步
模型比较
验证与诊断
反思与重试
审批与注册
```

默认选择当前正在执行的步骤；任务结束时选择验证诊断，若无诊断则选择最近有记录的步骤。运行开始后，新事件只更新状态徽标，不自动切走用户正在阅读的内容。“查看最新进展”由用户主动点击。

每一步统一回答五个问题：

1. **本步目标**：用一句通俗说明解释作用。
2. **输入**：数据版本、目标变量、样本分组、上游结果。
3. **实际执行**：算法、参数、操作顺序、开始与结束状态。
4. **结果**：主要图表、关键数值、可展开的明细表。
5. **依据与后续**：比较对象、选择规则、阈值、实际证据、下一步。

解释必须区分“算法的一般作用”和“本次为什么选择它”。后者来自结构化规则及执行事实；可以引用已记录的检索证据，但不得编造引用或把模型内部推理当作依据。

窄屏改为步骤选择器、图表、说明纵向排列；图例不能只靠颜色区分。所有交互提供键盘操作及表格替代。返回聊天、刷新链接、前进后退后仍定位到同一运行、尝试和步骤。

## 4. 各步骤的图表及验收行为

| 步骤 | 主图与内容 | 必须可操作的内容 | 事实约束 |
|---|---|---|---|
| 数据解释与审查 | 数据规模、字段角色、波长范围、目标分布、缺失汇总、代表性原始光谱 | 悬停读值，开关曲线，缩放波长，查看质量问题摘要 | 映射歧义显示等待确认；异常提示不能冒充已删除样本 |
| 数据划分 | Cal/Tuning/Holdout 的数量及目标分布，CV 折摘要 | 切换分组，查看划分方法、种子、隔离规则 | 不硬套三分法；实际无独立 Tuning 时展示真实协议 |
| 预处理 | 同批样本处理前后光谱、均值/分位带、候选评分 | 前后切换、联动波长缩放、点候选看有序参数 | 评分范围明确；没有保存中间变换时，只提供原始与最终处理结果 |
| 波长选择 | 全谱与保留区间、变量数、全谱基线与选择方案评分 | 刷选区间查看波长范围和变量数，点候选看规则 | 不运行时说明原因；未保存全路径分数时不绘制虚构迭代曲线 |
| 模型与调参 | 同口径候选误差、实际记录的参数搜索结果 | 点候选显示参数、状态、耗时和评分；筛选候选 | 区分已运行、失败、未触发；组合搜索只归因到组合，不能拆成独立算法贡献 |
| 验证与诊断 | 实测—预测散点、参考线、残差图、全量指标、质量门禁 | 散点与残差按样本联动、框选、查看所选点汇总 | 显示评估范围与单位；残差固定定义为预测值减实测值 |
| 反思与重试 | 尝试时间轴、方案差异、可比评分趋势 | 点尝试切换整页，查看与上次差异 | 计划与执行分开；未执行计划不能显示成已改进 |
| 审批与注册 | 质量门禁、审批、注册、Model Library 状态与产物 | 展开各状态证据、访问已有产物 | 审批、注册、入库分别记录；缺记录显示未知 |

用户体验验收示例：用户打开第 2 次尝试的“预处理”，看到实际执行顺序和选中规则；切换前后光谱并缩放同一波段；点击一个候选查看它的训练内分数；再进入“模型比较”查看组合参数；最后在“验证诊断”选择一个点，同时高亮其残差。返回第 1 次尝试时，标题、说明和图表必须一起切换。

## 5. 执行记录与证据契约

### 5.1 身份与事件

新增专用过程记录，不以截断的 `nir_workflow.history` 充当完整日志。`nir_workflow` 继续保存小摘要和过程索引引用，不放光谱矩阵、样本预测全集或图片 base64。

身份层级为 `thread_id → run_id → attempt_id → step_execution_id → chart_id`：

- 同一聊天可有多次独立建模；新建模使用新 `run_id`。
- 尝试在执行开始前分配稳定 `attempt_id`，展示编号另存。不要等待训练成功后才创建尝试。
- 每次步骤执行都有独立 `step_execution_id`；`step_key` 只表示数据审查、预处理等语义。
- 同一次工具调用的重复回放沿用原身份；真正重试创建新身份，并记录 `retry_of`。
- 数据解释和划分可作为运行级共享步骤，由各尝试显式引用；重用证据显示“沿用”，不伪造重新执行。
- `project_id` 是可空业务关联，不承担唯一身份或线程授权。

事件至少记录 `event_id`、单调递增 `sequence`、`run_id`、`attempt_id`（运行级可空）、`step_execution_id`、`event_type`、`source_tool`、`tool_call_id`、时间及引用。使用持久化事务分配序列并对幂等键设唯一约束；排序依赖序列，不依赖可能漂移的时间戳。

建议在既有持久化层增加过程事件及证据索引表，使用项目迁移机制。模型计算组件只输出执行事实和证据数据；后端适配层负责线程归属、存储和发布。前端从这些记录投影界面，不从聊天文本、文件名或当前阶段反推历史步骤。

若训练工具只在结束时提供内部步骤信息，页面运行中显示工具执行状态，结束后补充已记录的子步骤；不得凭固定计时模拟内部实时进度。

### 5.2 两套独立状态

| 状态域 | 取值 | 含义 |
|---|---|---|
| execution_status | pending / running / waiting_user / succeeded / failed / cancelled / interrupted / skipped / unknown | 执行情况；unknown 供旧记录无法确认时使用 |
| evidence_status | pending / available / partial / not_recorded / not_applicable / failed / unavailable | 证据是否存在及可读取 |

例如“训练完成 + 图表保存失败”显示成功的训练事实及图表失败提示，不能将模型改判为训练失败。质量门禁及注册所需的核心证据继续遵守原有强制规则；本方案的图表降级不放宽这些规则。

`waiting_user` 由实际等待事件驱动；`skipped` 必须带原因。服务重启后由恢复逻辑核对仍在运行的任务，确认失去执行者才标记 interrupted，不能仅凭页面轮询超时断言取消。

### 5.3 步骤详情及图表必需字段

| 对象 | 必需内容 |
|---|---|
| 过程摘要 | schema_version、run_id、revision、任务/数据摘要、尝试索引、步骤双状态、capabilities、更新时间 |
| 步骤详情 | 身份、输入/输出引用、实际方法及有序参数、决策事实、状态原因、证据列表、执行时间 |
| 证据引用 | evidence_id、不可变版本、sha256、类型、大小、生成来源、chart_schema_version；存储位置仅供服务端使用 |
| 图表 | chart_id、所属执行身份、图类型、轴名/单位、数据分组、评估口径、全量/返回数量、抽样信息、内容哈希、序列/点数据 |
| 决策事实 | baseline_id、candidate_id、实际分数、选择规则、阈值、选中结果、原因码、对应证据引用 |

未知字段用 null 加缺失原因，禁止用 0 代替。候选结果保存在专用完整记录中，详情分页返回；`decision_facts` 保留有界摘要。参数保留顺序、实际数值和实现来源，按允许字段输出，去除宿主机路径、凭据等无关内容。

P0 必须提交版本化 JSON Schema 和成功、跳过、失败、缺证据、旧会话、指标不可比六类契约样例；前后端以同一组样例验证兼容性。

## 6. 指标含义与比较规则

每条指标单独携带 `metric_name`、`value`、`direction`、`unit`、`evaluation_kind`、`validation_scope`、`metric_definition_version`、`n_evaluated` 和比较所需指纹。`evaluation_kind` 至少区分 calibration、cross_validation、tuning、holdout、external、unknown。

跨候选或跨尝试的可比性由服务端统一判断，并返回 `comparison_group_id` 与不兼容原因。严格比较以下内容：任务类型、数据内容与解释版本、目标身份与变换/单位、协议版本、实际样本划分指纹、适用时的 CV 折分指纹、评估方式、验证范围、指标定义与聚合方式、实际评估样本集合。缺少必要字段就不进入排名或趋势。

特征选择和预处理本身允许不同，否则无法比较优化效果；比较要求它们遵守相同训练边界和评估协议。相同划分方法名或相同随机种子不能代替实际样本指纹。

现有 `RMSECV` 字段不能直接决定显示名称：若生产路径证明来自 Tuning，就显示“调参集 RMSE”；若旧记录无法证实来源，显示“历史指标，评估方式未记录”。本次不通过批量重命名历史字段猜测或改写事实。

模型选择和优化趋势使用训练内 CV/Tuning 指标。Holdout/External 显示独立评估结果，不驱动候选推荐。若最终留出集曾被反复用于重试决策，必须记录并提示其已参与适应性选择，不能把它继续包装为未触碰的最终评估；可视化不得凭空提升已有科学有效性声明。

不可比尝试仍可并排查看配置和各自结果，但不连线、不计算改善率、不显示“最佳”。界面应解释具体原因，例如“实际验证样本不同”或“历史记录缺少划分信息”。

## 7. 证据存储、发布与读取

证据在真实计算路径中生成：审查时保存分布与光谱摘要，划分时保存成员关系指纹和汇总，预处理时保存同组前后数据，选择时保存候选及决策，预测时保存诊断数据。可从既有确定性结果导出，不能重新训练来补一张图。

写入流程固定为：受控临时位置完整写入 → 校验 schema/大小/哈希 → 原子发布不可变产物 → 事务登记索引及引用事件。远程沙箱须先完成回传与校验，再发布可用引用。同步中显示 pending，失败显示失败原因。

同一步重试不覆盖旧文件。崩溃留下的未引用产物由受控清理处理；清理只针对确认无引用的过程证据。线程删除进入现有清理生命周期，避免误删仍被 Dataset/Model Library 引用的资产。进程崩溃、回传失败、索引登记失败均需有重试与幂等测试。

图表专用证据写入失败可降级为缺图，保留已完成计算结果。重新读取或同步已有证据可以重试；缺失且无法恢复的旧数据不能静默重算。核心模型、审计、质量门禁证据失败仍按既有严格行为处理。

建议只读接口（新设计，实施时统一挂入现有 Gateway）：

```text
GET /api/threads/{thread_id}/nir-process/runs?cursor=...
GET /api/threads/{thread_id}/nir-process/runs/{run_id}
GET /api/threads/{thread_id}/nir-process/runs/{run_id}/steps/{step_execution_id}
GET /api/threads/{thread_id}/nir-process/runs/{run_id}/steps/{step_execution_id}/candidates?cursor=...
GET /api/threads/{thread_id}/nir-process/runs/{run_id}/charts/{chart_id}?version=...
```

摘要支持 ETag/条件请求；列表有分页与上限。成功读取但无图时返回明确的 evidence_status；未登录返回 401，不存在或无权访问的资源按现有统一策略处理且不暴露资源存在性；版本失配返回 409 并触发摘要刷新；限流和服务故障分别返回 429/5xx。图表损坏返回结构化不可用状态，不返回半份数据或默认为空数组。

## 8. 数据访问与刷新机制

线程所有者在已有会话数据权限内，默认可以查看本线程原始光谱及实测/预测坐标，无需每次额外授权。样本联动使用本线程内稳定的不透明 ID，原始姓名、文件路径等不进入图表响应；不透明 ID 不等于坐标匿名化。

服务端返回 `can_view_sample_points`、`can_view_raw_spectra` 等能力。受限身份、分享模式或部署策略不允许明细时，只提供获准的聚合图；若现有权限体系没有分享读取能力，本期不自行增加。每个接口及产物下载均校验用户、线程、运行、执行和证据归属，不能仅校验首页或信任客户端 project_id。禁止接受任意文件路径。

独立页面首期采用轮询：前台活跃运行每 3 秒检查摘要，退后台暂停，回前台立即刷新；终态获取一次最终摘要后停止，用户可手动刷新。摘要接口暂时失败时指数退避至最多 30 秒，显示更新时间；停止轮询前还需确认没有待同步图表证据。聊天中的状态更新可触发提前刷新，但不是独立页面的唯一数据源。

摘要 `revision` 单调递增；图表按不可变版本和哈希读取。查询缓存键必须包含用户/租户边界、线程、运行、步骤执行、图表 ID、图表版本和影响响应的权限能力。切换尝试时取消旧请求；即使取消未成功，也丢弃与当前身份不符的返回。旧图与旧标题可一起暂存，但不允许新标题配旧图。用户退出后清除相关缓存。

## 9. 数据规模与统计语义

默认加载摘要和当前步骤，其他步骤懒加载。建议首期接口预算：摘要不超过 200 KiB；单图响应不超过 1 MiB（均按未压缩 JSON）；光谱最多 20 条代表曲线、每条最多 1,000 个显示点；散点最多 2,000 个；候选每页最多 50 条。超过预算由后端进一步抽样、聚合或分页，前端不接收全量矩阵。

光谱代表曲线采用固定种子选样，可补充已识别异常样本；波长显示可使用按区间保留极值的压缩方法。明确记录选样、压缩算法版本及原始/显示数量，不声称压缩保留了全部细节。选择区间另按真实波长轴保留准确边界；原始光谱数据不因图表压缩而改变。

散点抽样保持主要分组覆盖；额外保留异常点时在图旁提示其可能高估视觉占比。均值/分位带及指标由后端基于明确的全量范围计算，不能由显示点回算成全量结果。

首期框选只汇总“当前显示的所选点”，始终显示这个范围及数量；小规模无抽样时才可说明覆盖全量。全量条件查询作为后续能力。指标卡始终保留全量分数及全量样本数，框选结果单独显示。

性能验收基准：至少覆盖 1,000 × 1,000 与 10,000 × 2,000 的光谱规模、20 次尝试和 200 个候选记录。测量对象是已有证据的页面读取，不包含模型训练耗时。在记录硬件、浏览器、网络条件和缓存状态的固定环境运行至少 30 次，目标 P95 首张可交互图不超过 3 秒，缓存步骤切换不超过 300 毫秒，悬停/刷选不超过 100 毫秒。阈值是本方案验收目标，尚未经实测；P0 应完成基线测量并记录任何调整理由。

## 11. 首期测试与最终验收

必须覆盖以下场景：

| 场景 | 预期结果 |
|---|---|
| 真实单目标任务顺利完成 | 数据审查、划分、预处理、模型比较、诊断有真实证据；波长选择按实际执行展示 |
| 波长选择未触发或候选失败 | 有原因与状态；不伪造曲线、分数或选中结果 |
| 训练完成但图表保存/同步失败 | 训练事实保留，图表明确失败；核心质量门禁行为不变 |
| 两次尝试参数改变或顺序改变 | 能逐项显示参数值与操作顺序的差异，不能只比较方法集合 |
| 数据/分组/CV/单位/口径不同或缺失 | 不排名、不连接趋势，给出不可比原因 |
| 同一工具回放、事件乱序、进程中断恢复 | 幂等、不重复尝试、不回退状态；历史证据不覆盖 |
| 快速切换尝试、网络请求乱序 | 标题、图表、说明来自同一执行身份 |
| 超过 50 个历史事件、8 个候选 | 详情仍完整可分页读取，不依赖原摘要截断长度 |
| 越权线程、跨运行图表引用、路径注入 | 请求被拒绝；响应不包含宿主机路径或其他线程数据 |
| 产物丢失、哈希不符、旧 schema、旧会话 | 明确不可用或当时未记录，不静默重算、不拼凑事实 |
| 大规模数据、下采样、样本框选 | 响应有界、全量指标不变、框选范围标注正确 |
| 窄屏、键盘、表格替代、页面刷新 | 核心探索动作可完成，定位与用户选择可恢复 |

后端以契约投影、幂等、状态恢复、授权、哈希校验和真实数值一致性为测试重点；前端覆盖比较逻辑、参数顺序差异、请求乱序和“点步骤 → 看图 → 点候选 → 切尝试 → 看依据”的端到端流程。依仓库规则执行相关测试与格式/类型检查，不用大量静态快照替代行为验证。

上线通过功能开关逐步启用，旧 Sheet 持续可用；关闭开关即可回到旧入口，保留已生成证据。新证据写入失败应可观测但日志不含原始样本数据。正式交付同步更新用户指南、README、接口文档及受影响模块的 AGENTS.md，并提交真实操作截图、测试结果和性能报告。
